Why Slope Trick Matters

Dynamic programming problems over continuous domain variables or large integer ranges often involve state transitions of the form $dp_i(x) = \min_y \{ dp_{i-1}(y) + \text{cost}(x, y) \}$. When the domain of $x$ is large (e.g., $10^9$), standard array-based dynamic programming fails due to memory and time constraints. Even coordinate compression becomes unusable when the transition cost function depends dynamically on continuous distance metrics, such as $ x - a_i|$.

Slope Trick is a data structure technique that optimizes dynamic programming algorithms where the state function $f(x)$ is continuous, piecewise-linear, and convex. Instead of evaluating $f(x)$ at discrete points, Slope Trick maintains $f(x)$ implicitly by tracking its minimum value $min\_f$ alongside two multisets of "knots" (change points) where the slope of $f(x)$ increases or decreases by $1$. Using max-heaps and min-heaps to represent these knots reduces complex functional transitions—such as prefix minima sweeps and function additions—to $O(\log N)$ priority queue operations.

Slope Trick represents a convex piecewise-linear function $f(x)$ using its minimum value $min\_f$ and the multiset of $x$-coordinates where its derivative changes. By managing these transition points in max- and min-priority queues, DP transitions like $f(x) \leftarrow \min_{y \le x} f(y) + |x - a_i|$ are computed in $O(\log N)$ time per step, turning $O(N^2)$ or $O(N \cdot \text{Range})$ DP problems into $O(N \log N)$ execution time.

Core Concepts and Terminology

A continuous function $f: \mathbb{R} \to \mathbb{R}$ is piecewise-linear if its domain can be partitioned into intervals over which $f(x)$ is a line segment $a x + b$. It is convex if its derivative $f'(x)$ is non-decreasing across its domain. The points where $f'(x)$ changes discretely are called knots (or slope change points).

Because $f'(x)$ changes only by integer increments in typical competitive programming and optimization tasks, any convex piecewise-linear function $f(x)$ can be uniquely identified by:

  1. The minimum value of the function, $min\_f = \min_x f(x)$.
  2. The interval $[L_{max}, R_{min}]$ where $f(x) = min\_f$ (the flat bottom where slope is $0$).
  3. A max-heap $L$ storing all knots to the left of $L_{max}$ (where slope changes by $+1$ as we move right).
  4. A min-heap $R$ storing all knots to the right of $R_{min}$ (where slope changes by $+1$ as we move right).

Formally, the function is expressed as:

$$f(x) = min\_f + \sum_{l \in L} \max(0, l - x) + \sum_{r \in R} \max(0, x - r)$$

How Slope Trick Works, Step by Step

Slope Trick maintains a convex function under three primary operations:

1. Adding an Absolute Distance Function $g(x) = \vert{}x - a\vert{}$

Adding $\vert{}x - a\vert{}$ increases the slope by $+1$ for $x > a$ and decreases the slope by $-1$ for $x \lt a$ (which is equivalent to adding a knot at $x = a$ to both $L$ and $R$).

  • Case 1 ($a \lt L_{max}$): The point $a$ falls in the left region. $min\_f$ increases by $L_{max} - a$. The old $L_{max}$ is pushed to $R$, and $a$ is added twice to $L$ (so $L.top()$ becomes $a$).
  • Case 2 ($a > R_{min}$): The point $a$ falls in the right region. $min\_f$ increases by $a - R_{min}$. The old $R_{min}$ is pushed to $L$, and $a$ is added twice to $R$.
  • Case 3 ($L_{max} \le a \le R_{min}$): The point $a$ falls inside the minimum range. $min\_f$ remains unchanged. $a$ is added once to $L$ and once to $R$.

2. Prefix Minimum Sweep $f_{new}(x) = \min_{y \le x} f_{old}(y)$

This operation is required when enforcing non-decreasing sequence constraints ($x_i \ge x_{i-1}$).

  • For all $x \ge L_{max}$, $f_{new}(x) = min\_f$ (the slope stays $0$).
  • All knots to the right of $L_{max}$ are removed, meaning Right Heap $R$ is completely cleared.

The control flow for updating a non-decreasing sequence DP ($dp_i(x) = \min_{y \le x} dp_{i-1}(y) + \vert{}x - a_i\vert{}$) follows this decision process:

Worked Example with a Full Trace

Consider the classic problem: Make Array Non-Decreasing with Minimum Total Absolute Modification (Codeforces 713C / LeetCode 2263).

Given array $A = [4, 1, 3, 2]$, we want to construct a non-decreasing array $B$ ($B_0 \le B_1 \le B_2 \le B_3$) minimizing $\sum_{i=0}^3 \vert{}A_i - B_i\vert{}$.

We initialize $min\_f = 0$ and an empty max-heap $L$.

Worked Example

Trace It by Hand

Question: Given array $A = [4, 1, 3, 2]$, what is the final minimum cost to make $A$ non-decreasing? How does the contents of the max-heap $L$ relate to the optimal sequence $B$?

Step 1: Trace $min\_f$:

  • $i=0, A[0]=4$: $L = \{4\}$, $min\_f = 0$.
  • $i=1, A[1]=1$: $1 \lt L.top()=4 \implies min\_f += 4 - 1 = 3$. $L$ pops $4$ and inserts $1$ twice $\implies L = \{1, 1\}$.
  • $i=2, A[2]=3$: $3 \ge L.top()=1 \implies min\_f$ stays $3$. $L$ inserts $3 \implies L = \{3, 1, 1\}$.
  • $i=3, A[3]=2$: $2 \lt L.top()=3 \implies min\_f += 3 - 2 = 1$ (Total $min\_f = 4$). $L$ pops $3$ and inserts $2$ twice $\implies L = \{2, 2, 1, 1\}$.

Step 2: Final Minimum Modification Cost = $min\_f = 4$.

Step 3: Reconstruction of Optimal Non-Decreasing Sequence $B$: Working backwards from the max-heap states yields $B = [2, 2, 2, 2]$ or $B = [1, 1, 2, 2]$ (both achieve modification cost $\vert{}4-1\vert{} + \vert{}1-1\vert{} + \vert{}3-2\vert{} + \vert{}2-2\vert{} = 3 + 0 + 1 + 0 = 4$).

Implementation in Python, C++, and Java

The following implementations compute the minimum cost to make an array non-decreasing using Slope Trick. All three programs feature identical logic, process the sample input $A = [4, 1, 3, 2]$, and produce identical terminal outputs.

import heapq

def solve_slope_trick(arr):
    # Max-heap L stored using negated values
    L = []
    min_f = 0

    for idx, x in enumerate(arr):
        if L and -L[0] > x:
            l_max = -heapq.heappop(L)
            min_f += l_max - x
            heapq.heappush(L, -x)
            heapq.heappush(L, -x)
        else:
            heapq.heappush(L, -x)

        print(f"Processing x = {x}: min_cost = {min_f}, heap top = {-L[0]}")

    print(f"\nFinal Minimum Cost: {min_f}")
    return min_f

if __name__ == "__main__":
    arr = [4, 1, 3, 2]
    solve_slope_trick(arr)

#include <iostream>
#include <vector>
#include <queue>

long long solve_slope_trick(const std::vector<long long>& arr) {
    // Max-heap L
    std::priority_queue<long long> L;
    long long min_f = 0;

    for (long long x : arr) {
        if (!L.empty() && L.top() > x) {
            long long l_max = L.top();
            L.pop();
            min_f += l_max - x;
            L.push(x);
            L.push(x);
        } else {
            L.push(x);
        }

        std::cout << "Processing x = " << x << ": min_cost = " << min_f
                  << ", heap top = " << L.top() << "\n";
    }

    std::cout << "\nFinal Minimum Cost: " << min_f << "\n";
    return min_f;
}

int main() {
    std::vector<long long> arr = {4, 1, 3, 2};
    solve_slope_trick(arr);
    return 0;
}

import java.util.Collections;
import java.util.PriorityQueue;

public class Main {
    public static long solveSlopeTrick(long[] arr) {
        // Max-heap L
        PriorityQueue<Long> L = new PriorityQueue<>(Collections.reverseOrder());
        long minF = 0;

        for (long x : arr) {
            if (!L.isEmpty() && L.peek() > x) {
                long lMax = L.poll();
                minF += lMax - x;
                L.add(x);
                L.add(x);
            } else {
                L.add(x);
            }

            System.out.println("Processing x = " + x + ": min_cost = " + minF
                               + ", heap top = " + L.peek());
        }

        System.out.println("\nFinal Minimum Cost: " + minF);
        return minF;
    }

    public static void main(String[] args) {
        long[] arr = {4, 1, 3, 2};
        solveSlopeTrick(arr);
    }
}

Complexity, Correctness, and Invariants

The time and space bounds of Slope Trick depend on priority queue operations over $N$ elements.

Algorithm / TechniqueTime ComplexityAuxiliary SpaceKey Assumptions / Domain
Slope Trick$O(N \log N)$$O(N)$DP functions must be continuous, piecewise-linear, and convex.
Coordinate Compression + 2D DP$O(N^2)$$O(N)$Discrete states; applicable to non-convex continuous costs.
Segment Tree + Coordinate Compression$O(N \log N)$$O(N)$Requires discretization of domain prior to tree construction.
Divide and Conquer DP / SMAWK$O(N \log N)$ or $O(N)$$O(N)$Monotonicity of decision points; rigid DP grid structure.

Correctness Invariant: At step $i$, the priority queue $L$ contains the set of slope change points for the convex piecewise-linear function $f_i(x) = \min_{y \le x} f_{i-1}(y) + \vert{}x - a_i\vert{}$. Because $\vert{}x - a_i\vert{}$ adds a slope change of $+1$ for $x > a_i$ and $-1$ for $x \lt a_i$, inserting $a_i$ twice maintains exact derivative integrity across all linear segments.

Variants, Pitfalls, and Optimizations

Slope Trick extends to several functional operations:

  1. Shift / Translation $f_{new}(x) = \min_{x - b \le y \le x - a} f_{old}(y)$:

Used in inventory smoothing or bounded movement problems. This shifts all knots in $L$ by $+a$ and all knots in $R$ by $+b$. Rather than modifying every heap element, maintain lazy offset tags shift_L and shift_R. 2. Both Left and Right Slopes: When prefix minimum is not applied, $R$ is preserved. Operations require checking both $L.top()$ and $R.top()$ to determine where $a_i$ lies relative to $[L_{max}, R_{min}]$.

Common Implementation Pitfalls:

  1. Pushing $a_i$ Only Once for $\vert{}x - a_i\vert{}$: The function $\vert{}x - a_i\vert{}$ has slope $-1$ for $x \lt a_i$ and $+1$ for $x > a_i$. The slope change at $a_i$ is $(+1) - (-1) = 2$. You must push $a_i$ twice into the heap when processing absolute distance functions.
  2. Integer Overflow in $min\_f$: Accumulating $min\_f += L.top() - x$ can exceed 32-bit signed integer limits ($2^{31}-1$) when $N = 10^5$ and $A_i = 10^9$. Always use 64-bit integers (long long in C++, long in Java).
  3. Strictly Increasing Sequence Transformation: To force $B_0 \lt B_1 \lt \dots \lt B_{N-1}$, transform the input array to $A_i' = A_i - i$ and solve the non-decreasing problem on $A'$.
