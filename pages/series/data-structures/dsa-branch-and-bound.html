Why Branch and Bound Matters

Suppose you can load at most ten units of weight into a vehicle. Each optional shipment has a weight and a value, and each can be selected at most once. Trying every subset guarantees the best answer, but the number of subsets doubles with each extra shipment. A greedy choice is fast and feasible, yet can miss a better combination. Branch and bound combines a systematic search with a proof that some unfinished choices cannot improve the answer already found.

The same idea applies to discrete optimization problems such as facility location, scheduling, routing, and integer programming. Backtracking asks whether a partial choice can still be feasible. Branch and bound adds a second question: even if this branch remains feasible, could its best possible completion beat the incumbent? If an optimistic bound says no, the whole branch can be discarded.

This lesson uses 0/1 knapsack maximization as a concrete implementation. You will distinguish feasible solutions from optimistic estimates, derive a fractional relaxation bound, trace both kinds of pruning, and implement a depth-first search with explicit state and exact arithmetic. The search returns one optimal subset and explains why its exponential worst case remains possible.

Branch and bound searches a partitioned space of candidate solutions while retaining the best feasible solution found so far. It discards a branch only when the branch is infeasible or a valid optimistic bound proves that no completion can strictly improve that incumbent.

Core Concepts and Terminology

For knapsack, item $j$ has positive integer weight $w_j$ and nonnegative integer value $v_j$. Choose $x_j\in\{0,1\}$ to solve

$$\max\sum_{j=0}^{n-1}v_jx_j\qquad\text{subject to}\qquad\sum_{j=0}^{n-1}w_jx_j\le W.$$

Every item is optional, so the empty subset is feasible and has value zero. The programs return the maximum value, the chosen subset's weight, and its original item IDs. They return one optimum; they do not promise the lightest, lexicographically smallest, or every tied optimal subset.

The incumbent is a known feasible subset with value $B$. For maximization, it provides a lower bound on the global optimum. For a search node $s$, let $\operatorname{OPT}(s)$ be the best integer value among its completions. A valid optimistic upper bound must satisfy

$$U(s)\ge\operatorname{OPT}(s).$$

Therefore prune when $U(s)\le B$: no completion can improve the saved solution. A feasible greedy packing is suitable for initializing $B$, but its value is generally not an upper bound. A fractional solution may be suitable for computing $U$, but generally cannot become the incumbent.

Sort the items by decreasing value-to-weight ratio, breaking equal ratios by original ID. A node at depth $i$ has fixed include/exclude decisions for the first $i$ sorted items. Its selected-ID stack, current weight $w$, current value $p$, and next index $i$ describe the residual problem. Items before $i$ that are absent from the stack were excluded. The stack alone is insufficient: selecting [0] after excluding item 1 describes a different residual problem from selecting [0] before deciding item 1.

How Branch and Bound Works, Step by Step

The bound comes from fractional knapsack. Keep the node's past decisions fixed, but permit fractions of remaining items. This enlarges the feasible set, so its maximum value cannot be smaller than the best integer completion. In decreasing density order, take whole remaining items while they fit, then take the fraction of the first item that fills the remaining capacity and stop.

Why does that order solve the relaxation? If a fractional packing uses some lower-density weight while a higher-density item still has available weight, exchange the same weight between them. Value cannot decrease. Repeating this exchange yields a packing with a whole prefix, at most one fractional item, and no later items.

If whole items add value $q$, and $r$ units of capacity remain for the next item of weight $w_k$ and value $v_k$, the fractional bound is

$$U_{\mathrm{frac}}=p+q+\frac{rv_k}{w_k}.$$

All feasible objective values are integers, so the tighter integer bound

$$U=p+q+\left\lfloor\frac{rv_k}{w_k}\right\rfloor$$

is still safe. If an integer $z\le U_{\mathrm{frac}}$, then $z\le\lfloor U_{\mathrm{frac}}\rfloor$. This floor operation is justified by the integer objective; it is not a general rounding rule for real-valued optimization. If all remaining items fit, simply add all their values.

The implementation follows this order:

  1. Copy and sort the items by exact density comparisons. To compare items $a$ and $b$, compare $v_aw_b$ and $v_bw_a$ instead of dividing into floating-point ratios.
  2. Optionally obtain a feasible greedy incumbent: scan the sorted list, taking a positive-value item whenever it fits and skipping items that do not. This whole-item heuristic differs from the bound calculation, which takes a fraction at the first nonfitting item and stops.
  3. On each recursive entry, increment nodes. If current weight exceeds capacity, increment infeasible and return. Positive weights make this failure irreversible within that include branch.
  4. For a feasible state, update the incumbent if the selected items' value is strictly better. Leaving every undecided item out completes that partial selection feasibly, so an update need not wait for depth $n$.
  5. If all items have been decided, count a feasible terminal leaf and return. Otherwise compute the upper bound. If $U\le B$, count a bound prune and return.
  6. Include the next item: push its original ID and add its weight and value. Recurse to $i+1$. On return, subtract that value and weight and pop its ID.
  7. Explore exclusion at $i+1$ using the restored parent state. The global incumbent retains every improvement found in the include subtree. After all branches return, output its saved witness.

Only branch-specific state is undone. The incumbent is a global record of a feasible solution, so restoring it to an older value would throw away progress and weaken later pruning. The saved incumbent IDs are copied from the current selection; they must not alias the mutable stack.

The code deliberately counts an overweight include call as a visit before rejecting it. An implementation that checks the weight before making that call can explore the same feasible states with a different node counter. Likewise, this implementation checks terminal leaves before computing their bound, which determines the trace's bounds and leaves totals.

Greedy seeding takes item 0, skips items 1 and 2 because they do not fit, takes item 3, and skips item 4. Its witness [0,3] weighs 8 and has value 75. Initialize $B=75$. For the root bound, take item 0 and $4/5$ of item 1:

$$U_{\mathrm{frac}}=60+\frac45\cdot49=99.2,\qquad U=99.$$

Since $99\gt75$, search must continue. Including item 0 also has upper bound 99. Trying to include item 1 or, after excluding it, item 2 produces weight 11, so those include calls fail immediately. With both items 1 and 2 excluded, the bound becomes $60+15+\lfloor(2\cdot28)/4\rfloor=89$.

Including item 3 next yields weight 8 and value 75. The fractional bound is still 89, so the solver explores item 4. Including it produces weight 12 and fails; excluding it reaches a leaf of value 75. Undo item 3. Now item 4 fits with item 0, and their value 88 improves the incumbent. The next leaf, item 0 alone, cannot improve it.

After undoing the entire item-0 include branch, exclude item 0. The bound is 98: take items 1 and 2 in full. Include item 1, then item 2. At this feasible partial selection the solver immediately saves value 98, then prunes its remaining choices because its upper bound is exactly 98. The two pending branches have upper bound 85 and are also pruned.

The three overweight calls are nodes 3, 5, and 8. The feasible terminal leaves are nodes 9, 11, and 12. Bounds are computed at eleven nonterminal feasible entries. The incumbent improves at node 11, from 75 to 88, and node 15, from 88 to 98. Bound prunes occur at nodes 15, 16, and 17.

For node 16, item 2 has been excluded after choosing item 1. Take item 3 fully and three quarters of item 4 in the relaxation:

$$U=49+15+\left\lfloor\frac{3\cdot28}{4}\right\rfloor=85\le98.$$

For node 17, both items 0 and 1 were excluded. Take item 2, item 3, and the same fraction of item 4, again obtaining 85. Both branches are settled without visiting their leaves. The final answer is value 98, weight 10, original IDs [1,2]. The active selection is empty and its weight and value are zero after all undo operations.

Trace It by Hand

Pause at node 13: item 0 is excluded, i=1, current weight and value are zero, and the incumbent is 88. Predict the upper bound, the next two include decisions, and whether the resulting value is saved before or after pruning.

Answer: the bound is 98 from taking items 1 and 2. Including item 1 reaches node 14; including item 2 reaches node 15, with weight 10 and value 98. Save the new incumbent first. Its upper bound is then 98, so prune its undecided items because they cannot strictly improve it.

Now disable greedy seeding. Prediction: the optimum and visit order are unchanged for this input. The search still visits 17 nodes, but makes four incumbent improvements, reaching 60, 75, 88, and 98, rather than only two. Seeding need not reduce the node count on every instance.

Implementation in Python, C++, and Java

Each panel is a complete runnable implementation of the same depth-first algorithm. Input weights and values are aligned by original zero-based item ID; sorting keeps that ID attached to each item. The constructor copies the inputs, sorts by decreasing exact density, and breaks density ties by ID. The returned IDs are sorted numerically for display, independently of search order.

The demonstration accepts up to 24 items. Capacity and each value are integers in $[0,10^9]$; weights are integers in $[1,10^9]$. Arrays must be non-null and have equal lengths. Python additionally rejects noninteger values rather than coercing them. Zero-value items are permitted; zero-weight and negative inputs are rejected. These assumptions keep capacity pruning monotone and the fractional bound well-defined.

C++ and Java use 64-bit arithmetic for weights, values, density cross-products, fractional numerators, and counters. A single product is at most $10^{18}$, and total selected weight or value is at most $24\cdot10^9$, within their signed 64-bit range. Do not raise the input limits without revisiting those products and totals. Python uses exact integers but observes the same accepted input range. No floating-point calculations appear in the solver.

solve resets the working selection and all counters, optionally seeds a feasible greedy solution, and runs the search to completion. The method can be called repeatedly with either seeding mode on the same object. It verifies the final selection, weight, and value were restored. The saved answer is copied, so later undo operations or another solve do not change a previous result.

Counters have the following meanings:

  • nodes: all recursive entries, including overweight calls, bound prunes, and feasible leaves.
  • bounds: upper-bound calculations at feasible nonterminal entries.
  • infeasible: calls rejected because their current weight exceeds capacity.
  • pruned: feasible nonterminal entries rejected by $U\le B$.
  • updates: strict incumbent improvements found during search, excluding initial greedy seeding.
  • leaves: feasible entries at depth $n$, whether or not they improve the answer.

The terminal categories partition all returns: an entry either branches, is infeasible, is bound-pruned, or is a feasible leaf. bounds is a work counter that overlaps branching and bound-pruned entries. The seed field is the initial feasible value, not an extra counter or an optimality claim.

from functools import cmp_to_key


class KnapsackBB:
    LIMIT = 1_000_000_000

    def __init__(self, capacity, weights, values):
        if type(capacity) is not int or not 0 <= capacity <= self.LIMIT:
            raise ValueError("capacity out of range")
        if len(weights) != len(values) or len(weights) > 24:
            raise ValueError("invalid item counts")
        for w, v in zip(weights, values):
            if (type(w) is not int or type(v) is not int or
                    not 1 <= w <= self.LIMIT or not 0 <= v <= self.LIMIT):
                raise ValueError("invalid weight or value")
        self.capacity = capacity
        self.items = [(i, w, v) for i, (w, v) in enumerate(zip(weights, values))]

        def compare(a, b):
            left, right = a[2] * b[1], b[2] * a[1]
            if left != right:
                return -1 if left > right else 1
            return (a[0] > b[0]) - (a[0] < b[0])

        self.items.sort(key=cmp_to_key(compare))

    def upper(self, index):
        remaining = self.capacity - self.weight
        bound = self.value
        for k in range(index, len(self.items)):
            _, w, v = self.items[k]
            if w <= remaining:
                remaining -= w
                bound += v
            else:
                bound += remaining * v // w
                break
        return bound

    def search(self, index):
        self.nodes += 1
        if self.weight > self.capacity:
            self.infeasible += 1
            return
        if self.value > self.best:
            self.best, self.best_weight = self.value, self.weight
            self.best_items = self.chosen.copy()
            self.updates += 1
        if index == len(self.items):
            self.leaves += 1
            return
        bound = self.upper(index)
        self.bounds += 1
        if bound <= self.best:
            self.pruned += 1
            return
        rid, w, v = self.items[index]
        self.chosen.append(rid)
        self.weight += w
        self.value += v
        self.search(index + 1)
        self.value -= v
        self.weight -= w
        self.chosen.pop()
        self.search(index + 1)

    def solve(self, seed=True):
        if type(seed) is not bool:
            raise ValueError("seed must be Boolean")
        self.weight = self.value = self.best = self.best_weight = 0
        self.chosen, self.best_items = [], []
        self.nodes = self.bounds = self.infeasible = self.pruned = 0
        self.updates = self.leaves = 0
        if seed:
            for rid, w, v in self.items:
                if v > 0 and self.best_weight + w <= self.capacity:
                    self.best_weight += w
                    self.best += v
                    self.best_items.append(rid)
        self.seed_value = self.best
        self.search(0)
        if self.weight != 0 or self.value != 0 or self.chosen:
            raise RuntimeError("undo failed")
        stats = [self.nodes, self.bounds, self.infeasible, self.pruned,
                 self.updates, self.leaves]
        return self.best, self.best_weight, sorted(self.best_items), self.seed_value, stats


def show(name, capacity, weights, values, seed=True):
    value, weight, items, initial, stats = KnapsackBB(capacity, weights, values).solve(seed)
    print(f"{name}: value={value}, weight={weight}, items=[" + ",".join(map(str, items)) + "]")
    labels = ("nodes", "bounds", "infeasible", "pruned", "updates", "leaves")
    print(f"seed={initial}, " + ", ".join(f"{k}={v}" for k, v in zip(labels, stats)) + ", restored=YES")

#include <algorithm>
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>
using namespace std;

struct Item { int id; long long weight, value; };
struct Result {
    long long value, weight, seed;
    vector<int> items;
    vector<long long> stats;
};

class KnapsackBB {
public:
    static constexpr long long LIMIT = 1000000000LL;
    long long capacity, weight=0, value=0, best=0, best_weight=0, seed_value=0;
    vector<Item> items;
    vector<int> chosen, best_items;
    long long nodes=0, bounds=0, infeasible=0, pruned=0, updates=0, leaves=0;

    KnapsackBB(long long cap, const vector<long long>& weights, const vector<long long>& values)
        : capacity(cap) {
        if (cap<0 || cap>LIMIT || weights.size()!=values.size() || weights.size()>24)
            throw invalid_argument("invalid capacity or item counts");
        for (size_t i=0;i<weights.size();++i) {
            if (weights[i]<1 || weights[i]>LIMIT || values[i]<0 || values[i]>LIMIT)
                throw invalid_argument("invalid weight or value");
            items.push_back({static_cast<int>(i),weights[i],values[i]});
        }
        sort(items.begin(),items.end(),[](const Item& a,const Item& b) {
            long long left=a.value*b.weight, right=b.value*a.weight;
            if (left!=right) return left>right;
            return a.id<b.id;
        });
    }

    long long upper(int index) const {
        long long remaining=capacity-weight, bound=value;
        for (int k=index;k<static_cast<int>(items.size());++k) {
            const Item& item=items[k];
            if (item.weight<=remaining) {
                remaining-=item.weight; bound+=item.value;
            } else {
                bound+=remaining*item.value/item.weight;
                break;
            }
        }
        return bound;
    }

    void search(int index) {
        ++nodes;
        if (weight>capacity) { ++infeasible; return; }
        if (value>best) {
            best=value; best_weight=weight; best_items=chosen; ++updates;
        }
        if (index==static_cast<int>(items.size())) { ++leaves; return; }
        long long bound=upper(index); ++bounds;
        if (bound<=best) { ++pruned; return; }
        const Item& item=items[index];
        chosen.push_back(item.id); weight+=item.weight; value+=item.value;
        search(index+1);
        value-=item.value; weight-=item.weight; chosen.pop_back();
        search(index+1);
    }

    Result solve(bool seed=true) {
        weight=value=best=best_weight=0;
        chosen.clear(); best_items.clear();
        nodes=bounds=infeasible=pruned=updates=leaves=0;
        if (seed) {
            for (const Item& item : items)
                if (item.value>0 && best_weight+item.weight<=capacity) {
                    best_weight+=item.weight; best+=item.value; best_items.push_back(item.id);
                }
        }
        seed_value=best;
        search(0);
        if (weight!=0 || value!=0 || !chosen.empty()) throw logic_error("undo failed");
        vector<int> result_items=best_items;
        sort(result_items.begin(),result_items.end());
        return {best,best_weight,seed_value,result_items,
                {nodes,bounds,infeasible,pruned,updates,leaves} };
    }
};

void show(const string& name,long long capacity,const vector<long long>& w,
          const vector<long long>& v,bool seed=true) {
    Result r=KnapsackBB(capacity,w,v).solve(seed);
    cout<<name<<": value="<<r.value<<", weight="<<r.weight<<", items=[";
    for (size_t i=0;i<r.items.size();++i) { if(i) cout<<','; cout<<r.items[i]; }
    cout<<"]\nseed="<<r.seed;
    vector<string> labels={"nodes","bounds","infeasible","pruned","updates","leaves"};
    for (size_t i=0;i<labels.size();++i) cout<<", "<<labels[i]<<'='<<r.stats[i];
    cout<<", restored=YES\n";
}

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class Main {
    static final class Item {
        int id;
        long weight,value;
        Item(int id,long weight,long value) { this.id=id; this.weight=weight; this.value=value; }
    }
    static final class Result {
        long value,weight,seed;
        List<Integer> items;
        long[] stats;
        Result(long value,long weight,long seed,List<Integer> items,long[] stats) {
            this.value=value; this.weight=weight; this.seed=seed;
            this.items=new ArrayList<>(items); this.stats=stats.clone();
        }
    }
    static final class KnapsackBB {
        static final long LIMIT=1_000_000_000L;
        long capacity,weight,value,best,bestWeight,seedValue;
        List<Item> items=new ArrayList<>();
        List<Integer> chosen=new ArrayList<>(),bestItems=new ArrayList<>();
        long nodes,bounds,infeasible,pruned,updates,leaves;

        KnapsackBB(long capacity,long[] weights,long[] values) {
            if(capacity<0 || capacity>LIMIT || weights.length!=values.length || weights.length>24)
                throw new IllegalArgumentException("invalid capacity or item counts");
            this.capacity=capacity;
            for(int i=0;i<weights.length;++i) {
                if(weights[i]<1 || weights[i]>LIMIT || values[i]<0 || values[i]>LIMIT)
                    throw new IllegalArgumentException("invalid weight or value");
                items.add(new Item(i,weights[i],values[i]));
            }
            items.sort((a,b)-> {
                long left=a.value*b.weight,right=b.value*a.weight;
                if(left!=right) return left>right ? -1 : 1;
                return Integer.compare(a.id,b.id);
            });
        }
        long upper(int index) {
            long remaining=capacity-weight,bound=value;
            for(int k=index;k<items.size();++k) {
                Item item=items.get(k);
                if(item.weight<=remaining) { remaining-=item.weight; bound+=item.value; }
                else { bound+=remaining*item.value/item.weight; break; }
            }
            return bound;
        }
        void search(int index) {
            ++nodes;
            if(weight>capacity) { ++infeasible; return; }
            if(value>best) { best=value; bestWeight=weight; bestItems=new ArrayList<>(chosen); ++updates; }
            if(index==items.size()) { ++leaves; return; }
            long bound=upper(index); ++bounds;
            if(bound<=best) { ++pruned; return; }
            Item item=items.get(index);
            chosen.add(item.id); weight+=item.weight; value+=item.value;
            search(index+1);
            value-=item.value; weight-=item.weight; chosen.remove(chosen.size()-1);
            search(index+1);
        }
        Result solve(boolean seed) {
            weight=value=best=bestWeight=0; chosen.clear(); bestItems=new ArrayList<>();
            nodes=bounds=infeasible=pruned=updates=leaves=0;
            if(seed) {
                for(Item item:items)
                    if(item.value>0 && bestWeight+item.weight<=capacity) {
                        bestWeight+=item.weight; best+=item.value; bestItems.add(item.id);
                    }
            }
            seedValue=best;
            search(0);
            if(weight!=0 || value!=0 || !chosen.isEmpty()) throw new IllegalStateException("undo failed");
            List<Integer> resultItems=new ArrayList<>(bestItems); resultItems.sort(Integer::compare);
            return new Result(best,bestWeight,seedValue,resultItems,
                              new long[] {nodes,bounds,infeasible,pruned,updates,leaves});
        }
    }
    static void show(String name,long capacity,long[] w,long[] v,boolean seed) {
        Result r=new KnapsackBB(capacity,w,v).solve(seed);

Complexity, Correctness, and Invariants

Let $n$ be the item count and $N$ the number of recursive entries, including infeasible calls. Analyze growing inputs rather than treating the demonstration's fixed limits as a constant-size problem. Density sorting costs $O(n\log(n+1))$ comparisons, and greedy initialization costs $O(n)$. Under the accepted integer limits, the arithmetic in each comparison fits in a machine integer.

At a feasible nonterminal entry, the bound scans at most $n-i$ remaining items. Copying a new incumbent's IDs costs at most $O(n)$, and ordinary include/undo operations are constant time. A conservative total bound is

$$T=O\bigl(n\log(n+1)+N(n+1)\bigr),\qquad N\le2^{n+1}-1.$$

Thus a conservative worst-case bound is $O((n+1)2^n+n\log(n+1))$. Branch and bound can still explore an exponentially large tree when the relaxation is weak or many branches remain competitive. There is no distribution-independent average-case improvement: item correlations, capacity, tie structure, and incumbent quality affect pruning.

In a best case such as root proof, $N=1$: sorting and one linear bound calculation settle the problem, giving $O(n\log(n+1))$ total time here. With an already sorted input, the corresponding search and initialization take $O(n)$. For an empty input, one terminal call takes constant time. A zero capacity also settles at the root for nonempty accepted inputs, since all weights are positive.

The search holds one mutable selection and at most $n+1$ recursive frames. The copied items, incumbent IDs, returned witness, and sorting workspace use $O(n)$ memory overall. It does not store all live siblings in a separate frontier. This distinguishes depth-first search from a best-bound implementation, which may retain exponentially many open nodes.

Correctness separates partitioning, feasibility, bounding, and undo. At depth $i$, including and excluding the next item partition every completion of the fixed prefix. Positive weights make an overweight selection permanently infeasible in that branch. For a feasible selection, taking no further items gives an immediate feasible witness, so every incumbent update is valid.

Relaxing the remaining binary decisions to fractions contains every integer completion. Density filling solves that relaxation; flooring its value preserves an upper bound on integer objectives. Hence $U\le B$ can remove only branches incapable of strict improvement. An equal-valued optimum may be discarded because the incumbent already supplies a witness of that value. Restoring the selection, weight, and value after inclusion makes the exclusion branch describe exactly the intended sibling problem. After the finite search has settled every branch, no better feasible selection remains, so the incumbent is optimal.

The incumbent always names an actual feasible selection, every node's upper bound dominates all its feasible completion values, and the include/exclude branches partition the node's remaining choices. Exact undo preserves those meanings across siblings, so feasibility pruning and $U\le B$ pruning cannot discard a strictly better solution.

Variants, Pitfalls, and Optimizations

Maximization versus minimization. For maximization, feasible incumbents are lower bounds on the optimum, and optimistic node estimates are upper bounds; prune when $U\le B$. For minimization, a feasible incumbent is an upper bound, and an optimistic node estimate is a lower bound; prune when $L\ge B$. The word “optimistic” means better than or equal to every attainable completion, with the inequality direction determined by the objective.

Feasible heuristics versus relaxations. The worked greedy packing of value 75 proves only that the optimum is at least 75. Calling that number an upper bound would falsely prune the root and lose the solution worth 98. Conversely, the fractional packing worth 99.2 is not a permissible 0/1 witness. Keep the bound and incumbent roles explicit even if a solver reports both as numbers.

Search strategy and warm starts. Depth first uses little memory and may find a complete feasible solution quickly. Best-bound search prioritizes the largest upper bound for maximization, while breadth first explores decision levels uniformly. All can be correct with sound pruning; they differ in incumbent discovery and frontier size. A better feasible warm start can strengthen pruning. The code applies the whole-item heuristic only at the root; running a completion heuristic at selected internal nodes may improve the incumbent earlier, at an additional cost.

Stronger bounds. The sum of all remaining values is a valid but often loose upper bound for this nonnegative-value problem. Fractional knapsack is tighter because it respects capacity. More general integer programs use LP relaxations, valid inequalities, and other problem-specific bounds; adding valid cutting planes gives branch and cut. A stronger bound is useful only when the saved search justifies its computation cost. Prefix sums and a search for the fractional break item can accelerate this fixed-order knapsack bound, while an exact residual DP can sometimes settle small subproblems directly.

Arithmetic and input assumptions. Density order is part of the bound's proof. A rounded ratio or an overflowing cross-product can put items in the wrong order and invalidate the claimed fractional optimum. The code therefore uses exact comparisons and validates limits before multiplication. Flooring is safe here because the objective is integer and the fractional value is computed exactly; a floating-point underestimate near an integer can still be unsafe. Real-valued objectives require an appropriate conservative bound rather than this integer truncation rule.

Zero-weight items with positive value would be worth preprocessing if zero weights were supported: take them once in 0/1 knapsack and adjust the objective. The shown implementation rejects zero weights instead. Negative weights would also invalidate the argument that an overweight prefix can never become feasible. The accepted input model is part of the algorithm's correctness conditions.

Ties and dominance. Pruning equality is correct when only one optimal witness is required. Enumerating every optimum needs strict bound pruning, appropriate tie collection, and a terminal policy that avoids reporting the same completed selection from several partial states. It is not obtained by changing one comparison alone. Be equally careful with item dominance: an item that is heavier and no more valuable than another cannot always be deleted in 0/1 knapsack, because an optimum may use both distinct items. State dominance requires the same remaining decisions and a proof that one partial state can replace the other.

Stopping early and reporting a gap. An incumbent alone gives a feasible answer. To report an optimality gap before exhaustion, maintain valid bounds for the entire open frontier, including pending siblings and the currently explored subproblem. For maximization,

$$B\le\operatorname{OPT}\le U_{\mathrm{global}},\qquad U_{\mathrm{global}}=\max\left(B,\max_{s\in\mathrm{OPEN}}U(s)\right).$$

The absolute gap is $U_{\mathrm{global}}-B$. With an empty frontier, define the global bound as $B$. The last visited node's bound is not necessarily a bound for the whole problem. The supplied recursive solver runs to completion and does not implement interruption or frontier-gap reporting. In other optimization problems, distinguish “no incumbent yet” from proven infeasibility; this optional-item knapsack always has the empty feasible solution.

Never replace an optimistic upper bound with the value of a merely feasible greedy packing, and never reverse the pruning inequality when changing objective direction. Restore branch state while retaining the best incumbent, use arithmetic that preserves the bound's proof, and treat equality pruning as a choice to return one optimum rather than every optimum.

Practice Problems and Real-World Use

Begin by checking small instances against every item subset. Validate both the claimed optimum and its witness: IDs must be distinct, weights must fit, and values must sum to the reported objective. Instrument bounds separately from node counts. A fast program with an invalid upper bound can produce a plausible but wrong answer; measuring fewer visits does not establish correctness.

The branch-and-bound framework extends beyond knapsack, but its bound must be re-derived for each problem. For facility location, a minimization relaxation can underestimate opening and shipping costs. For routing, a relaxation can underestimate the cost of completing a tour. For scheduling, a lower bound on achievable makespan can settle branches whose jobs still look feasible. A correct bound may ignore some constraints to become optimistic; it must not exclude legal completions while claiming to represent all of them.
