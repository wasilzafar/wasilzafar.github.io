Why Doubling Technique Matters

In pointer-based systems, trees, and functional graphs, navigating $K$ steps sequentially from a node requires traversing edges one by one in $O(K)$ time. When an application performs millions of queries—such as looking up the $K$-th ancestor of a node in a file system directory tree, finding the lowest common ancestor (LCA) of two network switches, or simulating state transitions over millions of time steps—naive linear traversal creates an insurmountable performance bottleneck.

The Doubling Technique (commonly known as Binary Lifting) overcomes this linear limitation by precomputing power-of-two jump targets. By storing $2^0, 2^1, 2^2, \dots, 2^j$ step pointers for every node, any step count $K$ can be decomposed into its binary representation $\sum b_i 2^i$. Jumping across these precomputed powers of two reduces $O(K)$ sequential traversals to $O(\log K)$ pointer hops. Precomputing this table requires $O(N \log K_{max})$ time and space, enabling instant $O(\log K)$ queries across massive structures.

The Doubling Technique precomputes jump targets at exponentially increasing intervals ($2^0, 2^1, 2^2, \dots$) to evaluate $K$-step transitions in $O(\log K)$ time. By expressing any integer $K$ as a sum of powers of two, long traversals are replaced with at most $\lfloor \log_2 K \rfloor + 1$ pointer operations.

Core Concepts and Terminology

The foundational element of the doubling technique is the binary lifting table, traditionally denoted as up[u][j] (or jump[u][j]).

  • Base Pointer (up[u][0]): The direct successor or immediate parent of node $u$ (a jump of $2^0 = 1$ step).
  • Recurrence Relation: A jump of length $2^j$ is composed of two consecutive jumps of length $2^{j-1}$:

$$up[u][j] = up[\,up[u][j-1]\,][j-1]$$

  • Binary Step Decomposition: To jump $K$ steps from node $u$, iterate through the bit positions of $K$ from highest to lowest. If the $j$-th bit of $K$ is set ($K \ \& \ (1 \ll j) \ne 0$), update $u \leftarrow up[u][j]$.

How Doubling Technique Works, Step by Step

Execution proceeds in two distinct phases: Table Precomputation and Query Processing.

Phase 1: Precomputation ($O(N \log N)$)

  1. Initialize up[u][0] with direct parent/successor pointers for all nodes $u \in [0, N-1]$.
  2. For exponent level $j = 1$ up to $\text{LOG}-1$: For each node $u$: compute up[u][j] = up[up[u][j-1]][j-1]. If up[u][j-1] is out-of-bounds or root, set up[u][j] to root or null.

Phase 2: Query Execution ($O(\log K)$)

To find the $K$-th ancestor/successor of node $u$:

  1. For $j = \text{LOG}-1$ down to $0$: If bit $j$ of $K$ is set ($K \ \& \ (1 \ll j)$): Update $u \leftarrow \text{up}[u][j]$.
  1. Return $u$.

Trace It by Hand

Scenario: Using the tree above (parent = [0, 0, 0, 1, 2, 2]), trace the execution of get_lca(4, 5).

  1. Depth Check: depth[4] = 2, depth[5] = 2. Both nodes are at equal depth.
  2. Loop $j = 1$ ($2^1 = 2$ steps): up[4][1] = 0, up[5][1] = 0. Both pointers equal 0. Since they match, we do not jump (jumping would overshoot past the LCA).
  3. Loop $j = 0$ ($2^0 = 1$ step): up[4][0] = 2, up[5][0] = 2. Both pointers equal 2. Since they match, we do not jump.
  4. Termination: Return up[4][0] = 2. The lowest common ancestor of nodes 4 and 5 is Node 2.

Implementation in Python, C++, and Java

The complete implementations below build the binary lifting table for a 6-node tree, execute $K$-th ancestor queries, and compute Lowest Common Ancestors (LCA). All three implementations produce identical terminal output.

class BinaryLifting:
    def __init__(self, n, parent, depth):
        self.n = n
        self.LOG = 4
        self.depth = depth
        self.up = [[0] * self.LOG for _ in range(n)]

        for i in range(n):
            self.up[i][0] = parent[i]

        for j in range(1, self.LOG):
            for i in range(n):
                self.up[i][j] = self.up[self.up[i][j - 1]][j - 1]

    def get_kth_ancestor(self, node, k):
        for j in range(self.LOG - 1, -1, -1):
            if (k >> j) & 1:
                node = self.up[node][j]
        return node

    def get_lca(self, u, v):
        if self.depth[u] < self.depth[v]:
            u, v = v, u

        diff = self.depth[u] - self.depth[v]
        u = self.get_kth_ancestor(u, diff)

        if u == v:
            return u

        for j in range(self.LOG - 1, -1, -1):
            if self.up[u][j] != self.up[v][j]:
                u = self.up[u][j]
                v = self.up[v][j]

        return self.up[u][0]

#include <iostream>
#include <vector>
#include <algorithm>

class BinaryLifting {
private:
    int n;
    int LOG;
    std::vector<int> depth;
    std::vector<std::vector<int>> up;

public:
    BinaryLifting(int n, const std::vector<int>& parent, const std::vector<int>& depth)
        : n(n), LOG(4), depth(depth), up(n, std::vector<int>(4, 0)) {

        for (int i = 0; i < n; ++i) {
            up[i][0] = parent[i];
        }

        for (int j = 1; j < LOG; ++j) {
            for (int i = 0; i < n; ++i) {
                up[i][j] = up[up[i][j - 1]][j - 1];
            }
        }
    }

    int getKthAncestor(int node, int k) const {
        for (int j = LOG - 1; j >= 0; --j) {
            if ((k >> j) & 1) {
                node = up[node][j];
            }
        }
        return node;
    }

    int getLCA(int u, int v) const {
        if (depth[u] < depth[v]) {
            std::swap(u, v);
        }

        int diff = depth[u] - depth[v];
        u = getKthAncestor(u, diff);

        if (u == v) {
            return u;
        }

        for (int j = LOG - 1; j >= 0; --j) {
            if (up[u][j] != up[v][j]) {
                u = up[u][j];
                v = up[v][j];
            }
        }

        return up[u][0];
    }
};

    int n = 6;
    std::vector<int> parent = {0, 0, 0, 1, 2, 2};
    std::vector<int> depth = {0, 1, 1, 2, 2, 2};

public class Main {
    static class BinaryLifting {
        private final int n;
        private final int LOG = 4;
        private final int[] depth;
        private final int[][] up;

        public BinaryLifting(int n, int[] parent, int[] depth) {
            this.n = n;
            this.depth = depth;
            this.up = new int[n][LOG];

            for (int i = 0; i < n; i++) {
                up[i][0] = parent[i];
            }

            for (int j = 1; j < LOG; j++) {
                for (int i = 0; i < n; i++) {
                    up[i][j] = up[up[i][j - 1]][j - 1];
                }
            }
        }

        public int getKthAncestor(int node, int k) {
            for (int j = LOG - 1; j >= 0; j--) {
                if (((k >> j) & 1) == 1) {
                    node = up[node][j];
                }
            }
            return node;
        }

        public int getLCA(int u, int v) {
            if (depth[u] < depth[v]) {
                int temp = u;
                u = v;
                v = temp;
            }

            int diff = depth[u] - depth[v];
            u = getKthAncestor(u, diff);

            if (u == v) {
                return u;
            }

            for (int j = LOG - 1; j >= 0; j--) {
                if (up[u][j] != up[v][j]) {
                    u = up[u][j];
                    v = up[v][j];
                }
            }

            return up[u][0];
        }
    }

    public static void main(String[] args) {
        int n = 6;
        int[] parent = {0, 0, 0, 1, 2, 2};
        int[] depth = {0, 1, 1, 2, 2, 2};

        BinaryLifting bl = new BinaryLifting(n, parent, depth);

        System.out.println("1st ancestor of node 5: " + bl.getKthAncestor(5, 1));
        System.out.println("2nd ancestor of node 5: " + bl.getKthAncestor(5, 2));
        System.out.println("2nd ancestor of node 3: " + bl.getKthAncestor(3, 2));
        System.out.println("LCA of node 3 and node 5: " + bl.getLCA(3, 5));
        System.out.println("LCA of node 4 and node 5: " + bl.getLCA(4, 5));
    }
}

Complexity, Correctness, and Invariants

Analyzing doubling algorithm complexity highlights its efficiency for multi-query operations.

Operation / StructurePrecomputation TimeQuery TimeAuxiliary SpaceKey Trade-offs
Doubling Technique$O(N \log N)$$O(\log K)$$O(N \log N)$Optimal general-purpose approach for trees and functional graphs.
Linear Pointer Hopping$O(N)$$O(K)$$O(N)$Minimal memory footprint, but unacceptably slow for large $K$.
Euler Tour + RMQ (Sparse Table)$O(N \log N)$$O(1)$$O(N \log N)$Instant LCA query time, but limited to static trees (cannot query $K$-th ancestor directly).
Heavy-Light Decomposition (HLD)$O(N)$$O(\log^2 N)$$O(N)$Supports path updates/queries; higher implementation complexity.

Binary Lifting Invariant: For any node $u$ and exponent $j \ge 1$, the table entry up[u][j] equals the node reached by taking $2^{j-1}$ steps from up[u][j-1]. Consequently, applying the sequence of jumps corresponding to the set bits of $K$ correctly reaches the exact $K$-step ancestor.

Variants, Pitfalls, and Optimizations

Common Variants

  1. Tree Path Aggregates: Storing $2^j$-step path minimums, maximums, or sums alongside node pointers (min_edge[u][j] = min(min_edge[u][j-1], min_edge[up[u][j-1]][j-1])).
  2. Functional Graphs (Cycles & Tails): Finding state after $K$ steps in graphs where every vertex has out-degree $1$.

Critical Pitfalls

Top Implementation Pitfalls:

  1. Overshooting LCA: When searching for LCA, jumping when up[u][j] == up[v][j] overshoots to higher common ancestors. You must jump only when up[u][j] != up[v][j] so execution halts exactly one level below the LCA.
  2. Insufficient LOG Size: Defining $\text{LOG}$ too small (e.g., $\text{LOG} = 16$ for $N = 100,000$) prevents jumps beyond $2^{15} = 32,768$, causing out-of-bounds queries to fail. Always ensure $2^{\text{LOG}-1} \ge N$.
  3. Uninitialized Boundary Values: Failing to point up[root][j] to root (or a designated sentinel node -1) leads to null pointer dereferences or infinite loops when $K$ exceeds the height of the tree.
