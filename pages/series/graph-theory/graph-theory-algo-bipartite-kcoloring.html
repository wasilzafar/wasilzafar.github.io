Bipartite Testing & k-Colorability Backtracking

October 4, 2026 Wasil Zafar 27 min read

Two colors reveal a hidden parity structure that BFS can certify—or refute with an odd cycle. With three or more colors, that deterministic propagation becomes a branching constraint search.

A Short History of Graph Coloring

Coloring began as a structural question—how many labels are needed so adjacent regions or vertices differ—and later became a central language for algorithmic complexity and constraint solving.

1936
Dénes Kőnig's foundational graph-theory text helped systematize bipartite graphs and the characterization by absence of odd cycles. That characterization is exactly what a modern two-color traversal tests.
1972
Richard Karp included the chromatic-number decision problem among his landmark NP-complete problems, establishing the hardness of general graph coloring.
1976
Michael Garey, David Johnson, and Larry Stockmeyer showed that graph 3-colorability remains NP-complete even under strong degree restrictions.
1979
Daniel Brélaz introduced DSATUR: choose the uncolored vertex exposed to the largest number of distinct neighbor colors. That idea remains valuable in exact search.

The resulting contrast is unusually sharp: 2-colorability has a linear-time structural test, while every fixed $k \geq 3$ gives an NP-complete decision problem on general graphs.

Historical sources: Karp (1972), Garey–Johnson–Stockmeyer (1976), and Brélaz (1979).

Coloring as a Constraint Problem

A proper $k$-coloring is a function $c:V\to\{0,\ldots,k-1\}$ satisfying $c(u)\ne c(v)$ for every edge $(u,v)$. Each color class is therefore an independent set. The smallest feasible $k$ is the chromatic number $\chi(G)$.

Decision

“Is $G$ colorable with at most $k$ colors?” The algorithms in this article answer this yes/no question and return a witness coloring when one exists.

Optimization

“What is $\chi(G)$?” Solve several decision problems, using clique lower bounds and heuristic upper bounds to narrow the candidate values of $k$.

proper: adjacent colors differbipartite ⇔ no odd cycleχ(G) is the minimum k

2-Colorability: BFS/DFS Bipartiteness Test

Two colors are special because an edge leaves no choice: once $c(u)$ is known, every neighbor $v$ must receive $1-c(u)$. A traversal can therefore propagate forced colors instead of guessing them.

Seed one component

Choose any uncolored vertex, assign color 0, and store parent and depth information. Repeat this step because the graph may be disconnected.

Propagate parity

For every explored edge $(u,v)$, give an uncolored $v$ the opposite color. In BFS, color is simply distance parity from the component seed.

Detect a contradiction

If an edge joins two vertices with the same color, stop: the edge and the two parent paths expose an odd cycle.

Return a certificate

If every component finishes without conflict, the two color classes are a constructive certificate that the graph is bipartite.

Why This Works

Every walk from the seed alternates colors. If two routes force different colors onto one vertex, their union contains an odd cycle. Conversely, without an odd cycle, every route to a vertex has the same parity, so the assignment is consistent.

Turning “No” into an Odd-Cycle Certificate

A boolean answer is useful; a witness is better. Keep a parent pointer for every discovered vertex. When a conflict edge $(u,v)$ joins equal colors, walk both parent chains to their lowest common ancestor $a$. Concatenate the path $u\leadsto a$, the reversed path $a\leadsto v$, and the conflict edge $(v,u)$.

Because $u$ and $v$ have the same parity, their tree path has even length. Closing it with one more edge makes the cycle odd. The Python implementation below returns this closed vertex sequence so callers can inspect, test, or display the exact obstruction.

yes-certificate: two color classesno-certificate: odd cycleself-loop: odd cycle of length 1

k-Colorability: Backtracking Search

For $k\geq3$, an edge no longer determines one forced choice: after seeing a red neighbor, a vertex may still choose blue, green, or another available color. The problem becomes a constraint-satisfaction search:

Variables and domains

Each vertex is a variable whose domain is ${0,\ldots,k-1}$. Assigning a color removes that color from every uncolored neighbor's domain.

Binary constraints

Every edge $(u,v)$ contributes the constraint $c(u)\ne c(v)$. A partial coloring is safe only while all assigned endpoints respect it.

Choose an uncolored vertex

A fixed order is correct, but a most-constrained-first order usually exposes contradictions earlier.

Try an available color

Skip colors already used by colored neighbors, assign a remaining color, and propagate the reduced domains.

Recurse or undo

If every vertex has a color, return the witness. If some uncolored vertex has no available color, undo the last choice and try another branch.

Search Heuristics & Propagation

Heuristics do not change which instances are colorable; they change how quickly the search discovers a witness or contradiction. The exact Python solver combines three inexpensive ideas:

  • DSATUR ordering: choose the uncolored vertex adjacent to the largest number of distinct colors. Break ties by degree, then vertex index for deterministic output.
  • Forward checking: after each assignment, reject immediately if any uncolored vertex has lost every color.
  • Color symmetry breaking: when a search component has no colored neighbor, try color 0 first. Renaming colors produces equivalent solutions, so symmetric root branches add no information.

Worked Example

Even cycle: propagation succeeds

For the square 0-1-2-3-0, start at vertex 0 with teal. BFS forces vertices 1 and 3 to navy, then vertex 2 to teal. The closing edge $(2,3)$ joins teal to navy, so no conflict appears.

$K_4$: three colors fail

Vertices 0, 1, and 2 form a triangle, so they must use three distinct colors. Vertex 3 is adjacent to all three; each candidate color conflicts with one neighbor. Every branch is equivalent up to renaming the three colors, so backtracking eventually proves that $K_4$ is not 3-colorable. A fourth color immediately supplies a witness.

Complexity Analysis

The two algorithms differ because propagation is complete for two colors but incomplete for three or more. Let $n=|V|$ and $m=|E|$.

ProblemWorst-case timeSpaceWhat is returned?
Bipartite test$O(n+m)$$O(n)$ besides the graphtwo color classes or an odd cycle
Exact $k$-color search$O(k^n(n+m))$ with straightforward checks; at most $k^n$ complete assignments$O(n+k)$ search statea $k$-coloring or failure after exhaustive search

The boundary cases are worth handling explicitly: $k=1$ succeeds only for an edgeless graph; $k=2$ should use the linear bipartite test; and any loop-free graph with $k\geq n$ is trivially colorable. For every fixed $k\geq3$, the decision problem is NP-complete on general graphs.

Implementation

The Python version returns both kinds of bipartite certificate and uses DSATUR plus forward checking for exact $k$-color search. The C++ and Java tabs keep the same graph model and demonstrate compact decision versions. All snippets assume an undirected adjacency list; each undirected edge must appear in both endpoint lists.

from collections import deque

def validate_undirected_graph(adj):
    """Return sorted, duplicate-free neighbor lists or raise ValueError."""
    n = len(adj)
    neighbors = []
    for row in adj:
        clean = set()
        for v in row:
            if not isinstance(v, int) or not 0 <= v < n:
                raise ValueError("neighbor index out of range")
            clean.add(v)
        neighbors.append(clean)

    for u, row in enumerate(neighbors):
        for v in row:
            if u not in neighbors[v]:
                raise ValueError("adjacency list must be symmetric")
    return [sorted(row) for row in neighbors]


def odd_cycle_from_conflict(u, v, parent):
    """Close the two parent paths with conflict edge (v, u)."""
    if u == v:                       # a self-loop
        return [u, u]

    path_u = []
    x = u
    while x != -1:
        path_u.append(x)
        x = parent[x]
    position = {x: i for i, x in enumerate(path_u)}

    path_v = []
    y = v
    while y not in position:
        path_v.append(y)
        y = parent[y]

    # u ... LCA ... v, followed implicitly by conflict edge v -> u
    return path_u[:position[y] + 1] + list(reversed(path_v)) + [u]


def is_bipartite(adj):
    """Return (is_bipartite, colors, odd_cycle_or_none)."""
    neighbors = validate_undirected_graph(adj)
    n = len(neighbors)
    color = [-1] * n
    parent = [-1] * n

    for start in range(n):
        if color[start] != -1:
            continue
        color[start] = 0
        q = deque([start])

        while q:
            u = q.popleft()
            for v in neighbors[u]:
                if color[v] == -1:
                    color[v] = 1 - color[u]
                    parent[v] = u
                    q.append(v)
                elif color[v] == color[u]:
                    cycle = odd_cycle_from_conflict(u, v, parent)
                    return False, color, cycle

    return True, color, None


def k_colorable(adj, k):
    """Return an exact k-coloring, or None if none exists."""
    if not isinstance(k, int) or k < 1:
        raise ValueError("k must be a positive integer")
    neighbors = validate_undirected_graph(adj)
    n = len(neighbors)

    if any(v in neighbors[v] for v in range(n)):
        return None
    if n == 0:
        return []
    if k == 2:
        ok, color, _ = is_bipartite(neighbors)
        return color if ok else None
    if k >= n:
        return list(range(n))

    colors = [-1] * n

    def used_colors(v):
        return {colors[u] for u in neighbors[v] if colors[u] != -1}

    def choose_vertex():
        uncolored = (v for v in range(n) if colors[v] == -1)
        return max(uncolored,
                   key=lambda v: (len(used_colors(v)), len(neighbors[v]), -v))

    def every_domain_nonempty():
        return all(colors[v] != -1 or len(used_colors(v)) < k
                   for v in range(n))

    def backtrack():
        if all(c != -1 for c in colors):
            return True

        v = choose_vertex()
        blocked = used_colors(v)
        candidates = [c for c in range(k) if c not in blocked]
        if not blocked:               # equivalent branches under color renaming
            candidates = [0]

        for c in candidates:
            colors[v] = c
            if every_domain_nonempty() and backtrack():
                return True
            colors[v] = -1
        return False

    return colors if backtrack() else None

# A 4-cycle: returns two color classes
square = [[] for _ in range(4)]
for u, v in [(0,1),(1,2),(2,3),(3,0)]:

k4 = [[1,2,3],[0,2,3],[0,1,3],[0,1,2]]

#include <iostream>
#include <vector>
#include <queue>

using namespace std;

bool isBipartite(int n, vector<vector<int>>& adj) {
    vector<int> color(n, -1);

    for (int start = 0; start < n; start++) {
        if (color[start] != -1) continue;
        color[start] = 0;
        queue<int> q; q.push(start);

        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : adj[u]) {
                if (color[v] == -1) {
                    color[v] = 1 - color[u];
                    q.push(v);
                } else if (color[v] == color[u]) {
                    return false;
                }
            }
        }
    }
    return true;
}

bool isSafe(int v, int c, vector<vector<int>>& adj, vector<int>& colors) {
    for (int u : adj[v]) if (u == v || colors[u] == c) return false;
    return true;
}

bool backtrackColor(int v, int n, int k, vector<vector<int>>& adj, vector<int>& colors) {
    if (v == n) return true;
    for (int c = 0; c < k; c++) {
        if (isSafe(v, c, adj, colors)) {
            colors[v] = c;
            if (backtrackColor(v + 1, n, k, adj, colors)) return true;
            colors[v] = -1;
        }
    }
    return false;
}

int main() {
    int n = 4;
    vector<vector<int>> adj(n);
    for (auto& e : vector<pair<int,int>>{{0,1},{1,2},{2,3},{3,0}}) {
        adj[e.first].push_back(e.second);
        adj[e.second].push_back(e.first);
    }
    cout << "Is bipartite: " << isBipartite(n, adj) << endl;

    vector<vector<int>> k4 = {{1,2,3},{0,2,3},{0,1,3},{0,1,2}};
    vector<int> colors(4, -1);
    cout << "3-colorable K4: " << backtrackColor(0, 4, 3, k4, colors) << endl;
    return 0;
}

import java.util.*;

public class BipartiteKColoring {
    public static boolean isBipartite(int n, List<List<Integer>> adj) {
        int[] color = new int[n];
        Arrays.fill(color, -1);

        for (int start = 0; start < n; start++) {
            if (color[start] != -1) continue;
            color[start] = 0;
            Deque<Integer> q = new ArrayDeque<>();
            q.add(start);

            while (!q.isEmpty()) {
                int u = q.poll();
                for (int v : adj.get(u)) {
                    if (color[v] == -1) {
                        color[v] = 1 - color[u];
                        q.add(v);
                    } else if (color[v] == color[u]) {
                        return false;
                    }
                }
            }
        }
        return true;
    }

    static boolean isSafe(int v, int c, List<List<Integer>> adj, int[] colors) {
        for (int u : adj.get(v)) if (u == v || colors[u] == c) return false;
        return true;
    }

    static boolean backtrack(int v, int n, int k, List<List<Integer>> adj, int[] colors) {
        if (v == n) return true;
        for (int c = 0; c < k; c++) {
            if (isSafe(v, c, adj, colors)) {
                colors[v] = c;
                if (backtrack(v + 1, n, k, adj, colors)) return true;
                colors[v] = -1;
            }
        }
        return false;
    }

    public static void main(String[] args) {
        int n = 4;
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        int[][] edges = {{0,1},{1,2},{2,3},{3,0}};
        for (int[] e : edges) {
            adj.get(e[0]).add(e[1]);
            adj.get(e[1]).add(e[0]);
        }
        System.out.println("Is bipartite: " + isBipartite(n, adj));

        List<List<Integer>> k4 = new ArrayList<>();
        int[][] k4Edges = {{1,2,3},{0,2,3},{0,1,3},{0,1,2}};
        for (int[] neighbors : k4Edges) {
            List<Integer> list = new ArrayList<>();
            for (int x : neighbors) list.add(x);
            k4.add(list);
        }
        int[] colors = new int[4];
        Arrays.fill(colors, -1);
        System.out.println("3-colorable K4: " + backtrack(0, 4, 3, k4, colors));
    }
}

Real-World Applications

The mathematical model is useful whenever pairwise incompatibilities must be separated. The graph must be defined carefully: vertices represent choices or resources, and an edge must mean “these two cannot share a group.”

Bipartite matching

Before running Hopcroft–Karp, a bipartite test verifies the required two-sided structure and supplies the left/right partition used by the matching algorithm.

Conflict scheduling

Model exams or jobs as vertices and overlaps as edges. A color is a time slot; minimizing colors corresponds to minimizing the number of slots under this simplified conflict model.

Register allocation

Compiler variables that are simultaneously live interfere. Coloring the interference graph maps nonadjacent variables to the same machine register.

SAT and CSP research

$k$-coloring is a compact source of hard constraint instances. It can be encoded with Boolean variables such as “vertex $v$ uses color $c$” and solved by a general SAT engine.

Operational value of certificates

A valid coloring can be checked by scanning every edge. When bipartiteness fails, an odd-cycle witness is equally easy to verify. These small certificates make failures explainable instead of leaving downstream code with an opaque false.

Exercises

1. Reconstruct the obstruction

Extend a DFS-based bipartite test to return an odd cycle. Why does a conflict edge between equal colors guarantee that the two tree depths have equal parity?

2. Test edge cases

Build cases containing an isolated vertex, multiple connected components, duplicate adjacency entries, and a self-loop. State the expected certificate for each before running the code.

3. Trace DSATUR

Run the vertex-selection rule by hand on $K_4$ with $k=3$. Record each vertex's saturation set after every assignment and identify the first empty domain.

4. Search for the chromatic number

Use a clique size as a lower bound and a greedy coloring as an upper bound. Repeatedly call the decision solver only for candidate values between those bounds.

5. SAT encoding challenge

Create a Boolean variable $x_{v,c}$ for each vertex-color pair. Add clauses requiring at least one color per vertex, at most one color per vertex, and different colors across each edge.

Limitations

The P vs. NP Cliff at k=3

There is no smooth complexity gradient here: 2-colorability is linear-time, but fixed-$k$ colorability is NP-complete for every $k\geq3$ on general graphs. DSATUR ordering and propagation may shrink the explored tree dramatically, but the worst case remains exponential.

  • Decision is not optimization: a successful $k$-coloring proves $chi(G)\leq k$, not that $k$ is minimal.
  • Model assumptions matter: these routines expect an undirected adjacency list. A self-loop makes every proper coloring impossible; parallel entries do not change colorability.
  • Recursion can be deep: exact search may reach depth $n$ and can require an iterative stack or a larger recursion limit in production environments.
  • Heuristics are instance-dependent: the best ordering can vary. Dense and sparse graphs may favor different tie-breakers, bounds, or decompositions.
