Weisfeiler-Leman Algorithm

September 27, 2026 Wasil Zafar 28 min read

A classical graph-isomorphism heuristic repeatedly recolors each vertex from the multiset of colors around it. That simple local process became a central language for explaining both the power and the limits of message-passing graph neural networks.

The Isomorphism Question

Two graphs are isomorphic when one can be relabeled to become the other: there is a bijection between vertices that preserves adjacency and, when present, vertex or edge labels. The difficulty is that vertex names carry no structural meaning. A useful test must describe vertices in a way that survives renaming.

Intuition: Neighborhood Fingerprints

At first, every unlabeled vertex looks identical. Ask each vertex what kinds of neighbors it has, replace its color with that answer, and repeat. A vertex's color gradually summarizes a larger neighborhood around it—without choosing an ordering for those neighbors.

The one-dimensional Weisfeiler–Leman algorithm, or 1-WL, maintains a partition of the vertices into color classes. Same color means “not yet distinguished by this test.” Different colors certify different rooted local structures at the current depth.

Initial color

Use one shared color for an unlabeled graph, or compress meaningful input labels/features.

Color class

Vertices that currently have the same structural summary belong to one class.

Compression

Map equal signatures to equal compact IDs and unequal signatures to unequal IDs.

Colors as Local Structural Summaries

At round $t+1$, vertex $v$ combines its old color with the multiset of colors on its neighbors:

$$c_{t+1}(v)=\operatorname{compress}\left(c_t(v),\ \operatorname{multiset}\{c_t(u):u\in N(v)\}\right).$$
  1. Read every vertex's colors from round $t$; do not update in place.
  2. Sort or count the neighbor colors so the signature is independent of adjacency-list order.
  3. Include the vertex's own old color, ensuring refinement may split a class but never merge two old classes.
  4. Assign the same new integer to identical signatures using one shared compression map.
  5. Stop when no color class splits.

Why a Multiset, Not a Set?

Multiplicity carries degree information. A vertex with neighbor colors {teal, teal, blue} must differ from one with {teal, blue}. A plain set would erase the repeated teal neighbor and weaken the test immediately.

Worked Refinement Trace

Consider edges $A-B$, $B-C$, $C-D$, and $C-E$. All vertices begin navy. Round one separates vertices by degree. Round two notices that leaf $A$ touches the degree-two vertex $B$, while leaves $D$ and $E$ touch the degree-three vertex $C$.

How to Compare Two Graphs Correctly

Color numbers have meaning only inside the compression system that created them. Refining two graphs independently and comparing only sorted class sizes is unsafe: two graphs can have classes of the same sizes produced by different signatures.

  1. Reject immediately if vertex counts or compatible input-label histograms differ.
  2. Form the disjoint union of the two graphs—no cross edges—and refine both components with one shared signature-to-color map.
  3. After every round, compare the color histogram in the first component with the histogram in the second.
  4. If a histogram differs, return definitely non-isomorphic. If refinement stabilizes with equal histograms, return inconclusive, not “isomorphic.”

One-Sided Verdict

Different synchronized color histograms are a proof of non-isomorphism. Equal histograms only mean that 1-WL has found no contradiction.

A Visual Failure Case

A six-cycle $C_6$ and two disjoint triangles $2C_3$ are plainly non-isomorphic—one graph is connected and the other is not. Yet every vertex has degree two and sees two neighbors of the same color in every round. Starting from one unlabeled color, 1-WL never splits either graph.

Soundness and Stabilization

Soundness follows by induction. An isomorphism preserves initial labels. If corresponding vertices have equal colors at round $t$, the isomorphism bijects their neighbors and therefore preserves the multiset of neighbor colors. Their next signatures—and compressed colors—remain equal. Thus an isomorphic pair can never develop different synchronized histograms.

Termination follows from refinement monotonicity. Including the old color means old classes never merge. Every non-stable round splits at least one class and increases the number of classes, which is at most $V$. The final partition is equitable: vertices in one class have the same number of neighbors in every color class.

What the Proof Does Not Say

It proves that histogram mismatch is impossible for isomorphic graphs. It does not prove the converse. The six-cycle example has equal histograms but no isomorphism between the graphs.

Connection to Message-Passing GNNs

A typical message-passing layer aggregates neighbor representations with a permutation-invariant operation, then updates each vertex from its previous representation and the aggregate. That mirrors the 1-WL signature rule.

$$h_v^{(t+1)}=\operatorname{UPDATE}\left(h_v^{(t)},\operatorname{AGG}\{h_u^{(t)}:u\in N(v)\}\right).$$

Under the standard message-passing model, such GNNs are at most as discriminative as 1-WL. With sufficiently expressive injective aggregation and update functions, architectures can match 1-WL's distinguishing power. Weaker aggregators may lose information—for example, a mean can erase multiplicity—so “bounded by 1-WL” does not mean every GNN automatically reaches the bound.

Higher-Dimensional WL

$k$-WL colors ordered $k$-tuples of vertices rather than individual vertices. Tuple relationships expose interactions that 1-WL cannot see, and increasing $k$ yields a stronger hierarchy of tests. The cost also rises sharply: there are $V^k$ tuples before refinement overhead, so higher-dimensional methods trade tractability for expressive power.

Beyond the 1-WL Ceiling

Practical models can add positional encodings, unique identifiers, subgraph features, higher-order states, or global mechanisms. Those additions change the information available to the model; they are not counterexamples to the 1-WL bound for plain local message passing.

Implementation

The safest comparison implementation refines the disjoint union of the two input graphs. That guarantees equal signatures in either component receive the same color ID. The routine below returns the full refinement history for inspection and uses a three-valued comparison result: different or inconclusive.

from collections import Counter

def compress(values):
    """Equal hashable values receive equal compact integer IDs."""
    palette, result = {}, []
    for value in values:
        if value not in palette:
            palette[value] = len(palette)
        result.append(palette[value])
    return result

def wl_refine(adj, initial_labels=None, max_rounds=None):
    n = len(adj)
    labels = [0] * n if initial_labels is None else list(initial_labels)
    if len(labels) != n:
        raise ValueError("one initial label is required per vertex")

    color = compress(labels)
    history = [color[:]]
    limit = n if max_rounds is None else max_rounds

    for _ in range(limit):
        signatures = [
            (color[v], tuple(sorted(color[u] for u in adj[v])))
            for v in range(n)
        ]
        new_color = compress(signatures)
        history.append(new_color[:])

        # Because the old color is in every signature, classes only split.
        stable = len(set(new_color)) == len(set(color))
        color = new_color
        if stable:
            break

    return color, history

def wl_compare(adj_g, adj_h):
    """Return ('different', round) or ('inconclusive', stable_round)."""
    if len(adj_g) != len(adj_h):
        return "different", 0

    n = len(adj_g)
    disjoint_union = [list(neighbors) for neighbors in adj_g]
    disjoint_union += [[u + n for u in neighbors] for neighbors in adj_h]
    _, history = wl_refine(disjoint_union)

    for round_no, colors in enumerate(history):
        if Counter(colors[:n]) != Counter(colors[n:]):
            return "different", round_no
    return "inconclusive", len(history) - 1

path4 = [[1], [0, 2], [1, 3], [2]]
star4 = [[1, 2, 3], [0], [0], [0]]

two_triangles = [[1, 2], [0, 2], [0, 1], [4, 5], [3, 5], [3, 4]]

print(wl_compare(path4, star4))            # ('different', 1)
print(wl_compare(cycle6, two_triangles))   # ('inconclusive', 1)

using namespace std;

using Signature = pair<int, vector<int>>;

vector<int> refine(const vector<vector<int>>& adj) {
    int n = adj.size();
    vector<int> color(n, 0);

    for (int r = 0; r < n; r++) {
        vector<Signature> signatures(n);
        for (int v = 0; v < n; v++) {
            vector<int> neighborColors;
            for (int u : adj[v]) neighborColors.push_back(color[u]);
            sort(neighborColors.begin(), neighborColors.end());
            signatures[v] = {color[v], neighborColors};
        }

        map<Signature, int> palette;
        vector<int> newColor(n);
        for (int v = 0; v < n; v++) {
            if (!palette.count(signatures[v]))
                palette[signatures[v]] = palette.size();
            newColor[v] = palette[signatures[v]];
        }

        int oldClasses = set<int>(color.begin(), color.end()).size();
        int newClasses = set<int>(newColor.begin(), newColor.end()).size();
        color = move(newColor);
        if (oldClasses == newClasses) break;
    }
    return color;
}

import java.util.*;

class WeisfeilerLeman {
    static int[] refine(List<List<Integer>> adj) {
        int n = adj.size();
        int[] color = new int[n];

        for (int r = 0; r < n; r++) {
            List<List<Integer>> signatures = new ArrayList<>();
            for (int v = 0; v < n; v++) {
                List<Integer> neighborColors = new ArrayList<>();
                for (int u : adj.get(v)) neighborColors.add(color[u]);
                Collections.sort(neighborColors);
                List<Integer> signature = new ArrayList<>();
                signature.add(color[v]);
                signature.add(-1); // separator; color IDs are nonnegative
                signature.addAll(neighborColors);
                signatures.add(signature);
            }

            Map<List<Integer>, Integer> palette = new HashMap<>();
            int[] newColor = new int[n];
            for (int v = 0; v < n; v++) {
                if (!palette.containsKey(signatures.get(v)))
                    palette.put(signatures.get(v), palette.size());
                newColor[v] = palette.get(signatures.get(v));
            }

            long oldClasses = Arrays.stream(color).distinct().count();
            long newClasses = Arrays.stream(newColor).distinct().count();
            color = newColor;
            if (oldClasses == newClasses) break;
        }
        return color;
    }

    public static void main(String[] args) {
        List<List<Integer>> adj = Arrays.asList(
            Arrays.asList(1), Arrays.asList(0,2),
            Arrays.asList(1,3), Arrays.asList(2)
        );
        int[] colors = refine(adj);
        System.out.println(Arrays.toString(colors));
    }
}

Using the Other Implementations for Comparison

The C++ and Java tabs show the single-graph refinement core. To compare graphs, offset the second graph's vertex indices, concatenate the adjacency lists into a disjoint union, run refine once, and compare the two component histograms—exactly as the Python tab does.

Complexity and Alternatives

There are at most $V-1$ strict splitting rounds. In the straightforward code above, sorting neighbor colors costs $\sum_v O(d(v)\log d(v))$ per round, bounded by $O(E\log V)$. Including signature construction and compression gives the conservative bound

$$O\!\left(V(E\log V+V)\right)$$

That bound describes the readable implementation, not the best possible color-refinement engine. Counting small integer colors and refining partitions with worklists avoids repeatedly sorting every neighborhood; established partition-refinement implementations can compute the stable coloring in $O((V+E)\log V)$ time.

Where 1-WL Is Useful

Case Study

Designing More Expressive Graph Neural Networks

Researchers use 1-WL as a clean baseline for asking which graph pairs a message-passing architecture could distinguish in principle. Higher-order states, positional features, subgraph counts, and global mechanisms can then be evaluated by the extra distinctions they enable.

Graph Neural NetworksMachine Learning Theory
  • Isomorphism prefilter: discard pairs proved different before invoking an exact algorithm.
  • Graph indexing: use refinement-derived summaries as inexpensive search keys, while remembering they are not unique canonical identifiers.
  • Feature engineering: count refined labels to summarize recurring local structures in graph classification pipelines.
  • Model diagnostics: build controlled graph pairs that expose what a GNN's aggregation rule preserves or loses.

Implementation Checklist

Validate adjacency indices; preserve multiplicities if parallel edges matter; decide how self-loops contribute; encode incoming and outgoing multisets separately for directed graphs; align input-label semantics; and never expose process-randomized hash values as persistent color IDs.

Historical Note and Takeaway

The method stems from work by Boris Weisfeiler and Andrei Leman in the late 1960s. Decades later, color refinement supplied the right abstraction for characterizing the expressive limits of neighborhood-aggregation graph neural networks.

The Mental Model to Keep

1-WL repeatedly replaces each vertex's color with a lossless code for “my previous color plus the multiset of my neighbors' colors.” A mismatch is a certificate of non-isomorphism; a match is only the end of this test's evidence. That one-sided logic is the key to using the algorithm—and its connection to GNNs—correctly.
