A Bit of History

Breadth-first search was independently discovered at least twice for very different purposes. In 1959, American computer scientist Edward F. Moore described a layer-by-layer search to find the shortest path through a maze — his paper, fittingly titled "The shortest path through a maze," is one of the earliest published uses. Around the same time, C. Y. Lee (a researcher at Bell Labs) independently devised essentially the same method in 1961 for a very unglamorous but hugely consequential problem: routing wires on a printed circuit board without crossing paths. To this day, "Lee's algorithm" is the name still used in the electronic-design-automation industry for grid-based wire routing — the same queue-driven, ring-by-ring search you now know as BFS.

Where the Algorithm Itself Lives

Breadth-First Search (BFS): The Core Guarantee

Recall from the BFS deep dive: Breadth-First Search (BFS) explores a graph layer by layer starting from a source vertex \(s\), using a First-In, First-Out (FIFO) queue to discover nodes in strict order of increasing distance.

The single most important property to remember: when BFS completes, \(\text{dist}[v]\) is guaranteed to equal the exact unweighted shortest path distance from \(s\) to \(v\) for every reachable vertex \(v\). Every application, algorithm, and structural proof in this section relies directly on this single guarantee.

Visual Intuition

Think of BFS as a Wave Expanding One Edge at a Time

BFS never dives down one branch. It finishes the entire current distance layer before moving to the next one. The FIFO queue is what preserves that order: vertices discovered earlier wait at the front, while newly discovered vertices join at the back.

Why the First Discovery Is a Shortest Path

To reach a vertex in layer 3, any route must use at least three edges from the source. BFS has already exhausted every possible route of lengths 0, 1, and 2 before layer 3 is processed. So the first time BFS reaches v, the recorded distance cannot later be improved by a shorter unweighted path.

The One Sentence to Remember

BFS explores by distance, not by branch: all vertices 1 edge away are handled before vertices 2 edges away, all distance-2 vertices before distance-3 vertices, and so on. The queue is the mechanism; shortest unweighted paths are the consequence.

Core Applications

Connected Components

Visual Intuition

A Connected Component Is a Reachability Island

Before connecting this to BFS, it helps to slow down and ask what a "connected component" actually is. Picture a social-network graph where an edge means "these two people are friends." Some clusters of people are all mutually reachable through some chain of friendships, but someone in an entirely separate cluster has no such chain to them at all, no matter how long a chain you're willing to trace. Each of these maximal clusters — where every member can reach every other member, but nobody outside can — is a connected component. A graph is "connected" precisely when it consists of a single component; most real graphs (social networks with isolated cliques, road maps with disconnected islands, computer networks with unreachable segments) are not connected, and figuring out where the component boundaries lie is often the very first question you need answered before any other graph algorithm can safely run.

Connected ComponentsReachability

Recall the equivalence relation from Part 1: define \(u \sim v\) to mean "a path exists between \(u\) and \(v\)." Checking the three equivalence-relation axioms confirms this is a legitimate equivalence relation, not just a convenient label:

  • Reflexive: \(u \sim u\) — the empty path (zero edges) trivially connects a vertex to itself.
  • Symmetric: if \(u \sim v\) then \(v \sim u\) — in an undirected graph, walking any path backwards is still a valid path.
  • Transitive: if \(u \sim v\) and \(v \sim w\) then \(u \sim w\) — splice the two paths together through \(v\) to get a walk from \(u\) to \(w\), and every walk contains a genuine path.

For any vertex \(v\), its equivalence class is the set \([v] = \{u \in V : u \sim v\}\) — every vertex reachable from \(v\) by some path (and, by symmetry, every vertex from which \(v\) itself is reachable). The three axioms together guarantee that these classes behave exactly the way "components" should:

  • Reflexivity guarantees every vertex belongs to some class — its own, at minimum — so no vertex is ever left out, unlabeled.
  • Symmetry guarantees a class is well-defined no matter which vertex you start counting from: if \(u \in [v]\) then \(v \in [u]\), so \([u] = [v]\) — the class has no single "correct" starting point.
  • Transitivity guarantees no two distinct classes can overlap. Suppose \([u]\) and \([v]\) shared some common vertex \(w\): then \(u \sim w\) and \(v \sim w\), so by symmetry \(w \sim v\), and by transitivity \(u \sim v\) — meaning \(u\) and \(v\) were secretly in the very same class all along, never two separate ones.

This is precisely the classical Fundamental Theorem of Equivalence Relations: every equivalence relation on a set induces a unique partition of that set into disjoint, exhaustive equivalence classes, and conversely, every partition of a set defines an equivalence relation ("same block as") that reproduces it. Applied here, it says \(\sim\) partitions \(V\) cleanly into disjoint equivalence classes — and those classes are exactly the graph's connected components. Every vertex lands in exactly one component: none is ever split across two, and no two components silently overlap.

BFS computes this partition directly, with no separate machinery required:

  1. Pick any vertex that hasn't been visited yet and run BFS from it.
  2. Every vertex BFS reaches during this run is, by definition, path-connected to the starting vertex — so all of them belong to the same equivalence class. Label them all with the current component number.
  3. When that BFS run's queue empties, the entire component has been fully labeled. If unvisited vertices remain, pick any one of them and repeat from step 1 with the next component number.
  4. Stop once every vertex has been visited and labeled.

Why the Total Cost Is Still O(V+E), Not O(V+E) Per Component

Each individual BFS run only ever touches the vertices and edges of its own component — it can never see, let alone revisit, a vertex belonging to another. So if the graph splits into components of sizes \(V_1, V_2, \dots, V_k\) with edge counts \(E_1, E_2, \dots, E_k\), the total work across every run is \(\sum_i O(V_i + E_i) = O(V + E)\) overall, since \(\sum_i V_i = V\) and \(\sum_i E_i = E\) — every vertex and edge is charged to exactly one BFS run, never more than once.

from collections import deque, defaultdict

def connected_components(adj, vertices):
    """Labels every vertex with a component id using repeated BFS."""
    component_of = {}
    component_id = 0
    for start in vertices:
        if start in component_of:
            continue  # already labeled by an earlier BFS run
        component_of[start] = component_id
        queue = deque([start])
        while queue:
            u = queue.popleft()
            for v in adj[u]:
                if v not in component_of:
                    component_of[v] = component_id
                    queue.append(v)
        component_id += 1
    return component_of, component_id  # vertex -> component label, total count

adj = defaultdict(list, {"A": ["B"], "B": ["A"], "C": ["D"], "D": ["C"], "E": []})
labels, count = connected_components(adj, ["A", "B", "C", "D", "E"])
print(labels, count)  # {'A': 0, 'B': 0, 'C': 1, 'D': 1, 'E': 2} -- 3 components
Visual Intuition

One BFS Run Finds Exactly One Connected Component

BFS cannot cross a gap where no edge exists. So a run started inside one component floods that entire component and then stops. Restarting from an unvisited vertex discovers the next component.

Testing Bipartiteness

Part 4 previewed the claim: a graph is bipartite if and only if it has no odd cycle. BFS gives the constructive half of that proof. Run BFS from any vertex, and 2-color every vertex by the parity of its BFS layer — even layers get color 0, odd layers get color 1. Because BFS visits a vertex only once, this coloring is well-defined. The graph is bipartite exactly when no edge connects two same-colored vertices.

Visual Intuition

BFS Layers Give a Natural Two-Coloring

Color every even BFS layer teal and every odd layer crimson. If every edge crosses between the two colors, the graph is bipartite. An edge joining two vertices in the same parity layer immediately exposes a conflict.

Worked Example

Why a Same-Layer Edge Means an Odd Cycle

Suppose BFS finds an edge \((u,v)\) where \(u\) and \(v\) are in the same layer \(k\) (so \(\text{dist}[u] = \text{dist}[v] = k\)). Both have a path of length \(k\) back to the source via their BFS parents. Following \(u\)'s path back to the source, across to \(v\) via the edge \((u,v)\), then back down \(v\)'s path to \(v\) traces a closed walk of length \(k + 1 + k = 2k+1\) — always odd. A careful argument (removing any repeated shared prefix of the two paths) turns this closed walk into an honest odd cycle, proving the graph is not bipartite.

BipartitenessBFS Layers
from collections import deque, defaultdict

def is_bipartite(adj, source):
    """Returns (bipartite: bool, coloring: dict) using BFS layer parity."""
    color = {source: 0}
    queue = deque([source])
    while queue:
        u = queue.popleft()
        for v in adj[u]:
            if v not in color:
                color[v] = 1 - color[u]
                queue.append(v)
            elif color[v] == color[u]:
                return False, color   # same-color edge found -> odd cycle exists
    return True, color

adj = defaultdict(list, {"A": ["B", "D"], "B": ["A", "C"], "C": ["B", "D"], "D": ["C", "A"]})
print(is_bipartite(adj, "A"))  # (True, {'A': 0, 'B': 1, 'D': 1, 'C': 0}) -- it's a 4-cycle

BFS for Web Crawling

Model the web as a directed graph: pages are vertices, hyperlinks are edges. A crawler starting from a set of seed URLs uses BFS almost verbatim — a frontier queue of discovered-but-unvisited URLs, a visited set (with URL normalization to avoid treating example.com/ and example.com as different vertices), and level-by-level expansion. The BFS property that matters here isn't shortest paths — it's breadth-first prioritization: a crawler wants to discover many distinct sites early rather than tunnel deep into one site's link structure first (which a DFS-style crawler would do). Production crawlers add rate limiting ("politeness" — don't hammer one server), distributed frontier queues across many machines, and re-crawl scheduling, but the discovery order underneath is still BFS.

Why BFS Fits Crawling

Advanced BFS Variants

Multi-source BFS starts with several sources already in the queue at distance 0 instead of one — useful for "distance to the nearest of these K locations" problems (nearest hospital, nearest exit). It is exactly ordinary BFS on a graph with an added virtual super-source connected to every real source with weight-0 edges.

Bidirectional BFS runs two BFS searches simultaneously — one forward from the source, one backward from the target — and stops the moment their frontiers meet. Since each search only needs to reach roughly half the true distance, this can reduce a search visiting \(O(b^d)\) vertices (branching factor \(b\), depth \(d\)) down to roughly \(O(2b^{d/2})\) — a dramatic saving on graphs with high branching factor, like word-ladder puzzles or friend-of-friend social searches.

The BFS idea survives several useful modifications. What changes is where the frontier begins or which end of the deque receives a newly discovered state.

0-1 BFS

Ordinary BFS works because every edge effectively costs 1. The moment edges have different costs, FIFO order is no longer enough. The special case of costs 0 and 1 is just structured enough that a deque can restore the correct distance order without a full priority queue.

A clever hybrid for graphs whose edges are weighted only 0 or 1 (common in grid problems — "some moves are free, some cost one step"): instead of a plain queue, use a deque. Push weight-0 edges to the front and weight-1 edges to the back. This keeps the deque's contents sorted by distance at all times without needing a full priority queue, giving Dijkstra-correct shortest paths in plain \(O(V+E)\) time — strictly faster than paying for a binary heap's \(O(\log V)\) factor when weights are this restricted.

Conclusion & Next Steps

BFS's one guarantee — visiting vertices in strict order of distance — turns out to prove bipartiteness, compute connected components, and (in its bidirectional and 0-1 forms) solve harder shortest-path variants without ever needing a priority queue.
