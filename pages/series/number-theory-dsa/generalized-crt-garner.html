Generalized CRT & Garner's Algorithm

Reconstruct residues with non-coprime and large moduli.

Intuition, Vocabulary and Foundations

A congruence describes a repeating schedule. The statement $x\equiv a\pmod m$ means every valid value differs from $a$ by a multiple of $m$. Combining congruences resembles synchronizing clocks: their requested readings may align periodically, or a shared cycle may make them contradictory.

For example, $x\equiv2\pmod6$ and $x\equiv5\pmod9$ are compatible because $\gcd(6,9)=3$ divides $5-2=3$. Their solutions form one residue class modulo $\operatorname{lcm}(6,9)=18$, namely $x\equiv14\pmod{18}$. In contrast, $x\equiv2\pmod6$ and $x\equiv4\pmod9$ are inconsistent because $3\nmid2$.

The generalized Chinese Remainder Theorem permits non-coprime moduli. Two constraints are compatible exactly when their residues agree modulo the gcd; after a successful merge, the combined modulus is the lcm, not generally the product.

Garner’s algorithm addresses pairwise coprime moduli. It reconstructs a value through mixed-radix digits $x=c_0+c_1m_0+c_2m_0m_1+\cdots$, where $0\le c_i\lt m_i$. Each digit satisfies the next congruence without disturbing previous ones. The representation is unique below $\prod_i m_i$ and can be evaluated exactly or modulo a separate target.

Generalized CRT first checks whether residues agree modulo every shared gcd; only compatible constraints may be merged, and the resulting period is their lcm. Garner’s algorithm instead requires pairwise coprime moduli and replaces a potentially huge direct reconstruction with uniquely determined mixed-radix digits.

Step-by-Step Derivations and Algorithms

To merge $x\equiv a\pmod m$ and $x\equiv b\pmod n$, write $x=a+mt$. Substitution gives $mt\equiv b-a\pmod n$. Let $g=\gcd(m,n)$. A solution exists exactly when $g\mid(b-a)$. Divide by $g$ to obtain

$$ \frac{m}{g}t\equiv\frac{b-a}{g}\pmod{\frac{n}{g}}. $$

The reduced coefficient $m/g$ is invertible modulo $n/g$, so solve for $t$, substitute into $a+mt$, and normalize modulo $m(n/g)=\operatorname{lcm}(m,n)$. Repeating this merge maintains that the current residue class equals the intersection of all processed constraints.

For pairwise coprime moduli, Garner assumes digits $c_0,\ldots,c_{i-1}$ are fixed. If $x_{i-1}$ is their partial mixed-radix value, the next digit satisfies

$$ x_{i-1}+c_i\prod_{j=0}^{i-1}m_j\equiv r_i\pmod{m_i}. $$

The accumulated product is invertible modulo $m_i$, so $c_i$ is unique. Once all digits are known, evaluate them with arbitrary-precision integers or reduce each accumulation step modulo a target.

Incremental CRT preserves that the current class is exactly the intersection of all processed constraints; compatibility and the reduced inverse prove each merge. Merging $k$ constraints takes $O(k)$ gcd and inverse operations, while straightforward Garner takes $O(k^2)$ modular operations and $O(k)$ storage.

Implementation, Complexity and Engineering

The reference implementation separates generalized CRT from Garner reconstruction. merge_crt accepts non-coprime moduli and returns None on contradiction. Garner checks pairwise coprimality before producing digits, preventing a nonexistent inverse from being mistaken for an unrelated failure.

Python integers grow automatically. In fixed-width languages, compute lcm as (m / gcd) * n, check multiplication, and use overflow-safe modular multiplication. Modular Garner keeps accumulated products reduced by the target modulus, but digit construction still uses arithmetic modulo the original source moduli.

from math import gcd


def extended_gcd(a, b):
    old_r, r = a, b
    old_x, x = 1, 0
    old_y, y = 0, 1
    while r:
        quotient = old_r // r
        old_r, r = r, old_r - quotient * r
        old_x, x = x, old_x - quotient * x
        old_y, y = y, old_y - quotient * y
    return old_r, old_x, old_y


def inverse_mod(value, modulus):
    if modulus <= 0:
        raise ValueError("modulus must be positive")
    divisor, coefficient, _ = extended_gcd(value % modulus, modulus)
    if divisor != 1:
        raise ValueError("inverse does not exist")
    return coefficient % modulus


def normalize_congruence(residue, modulus):
    if modulus <= 0:
        raise ValueError("modulus must be positive")
    return residue % modulus, modulus


def merge_crt(left, right):
    a, m = normalize_congruence(*left)
    b, n = normalize_congruence(*right)
    common = gcd(m, n)
    difference = b - a
    if difference % common != 0:
        return None

    reduced_m = m // common
    reduced_n = n // common
    step = 0 if reduced_n == 1 else (
        difference // common * inverse_mod(reduced_m, reduced_n)
    ) % reduced_n

    combined_modulus = m * reduced_n
    combined_residue = (a + m * step) % combined_modulus
    return combined_residue, combined_modulus


def generalized_crt(congruences):
    result = (0, 1)
    for congruence in congruences:
        result = merge_crt(result, congruence)
        if result is None:
            return None
    return result


def require_pairwise_coprime(moduli):
    for i, left in enumerate(moduli):
        if left <= 1:
            raise ValueError("Garner moduli must exceed 1")
        for right in moduli[:i]:
            if gcd(left, right) != 1:
                raise ValueError("Garner moduli must be pairwise coprime")


def garner_digits(residues, moduli):
    if len(residues) != len(moduli):
        raise ValueError("residue and modulus counts differ")
    require_pairwise_coprime(moduli)
    digits = []
    for i, (residue, modulus) in enumerate(zip(residues, moduli)):
        partial = 0
        multiplier = 1
        for j in range(i):
            partial = (partial + digits[j] * multiplier) % modulus
            multiplier = (multiplier * moduli[j]) % modulus
        digit = (
            (residue - partial) * inverse_mod(multiplier, modulus)
        ) % modulus
        digits.append(digit)
    return digits


def garner_exact(residues, moduli):
    digits = garner_digits(residues, moduli)
    value = 0
    multiplier = 1
    for digit, modulus in zip(digits, moduli):
        value += digit * multiplier
        multiplier *= modulus
    return value, multiplier


def garner_mod(residues, moduli, target_modulus):
    if target_modulus <= 0:
        raise ValueError("target modulus must be positive")
    digits = garner_digits(residues, moduli)
    value = 0
    multiplier = 1
    for digit, modulus in zip(digits, moduli):
        value = (value + digit * multiplier) % target_modulus
        multiplier = (multiplier * modulus) % target_modulus
    return value

Applications, Case Studies and Exercises

Generalized CRT suits schedules, counters, and constraints whose moduli may share factors. Garner is especially useful when a large integer or polynomial coefficient was computed modulo several machine-friendly primes and only a final modular value is required.

Practice

Apply Generalized CRT & Garner's Algorithm

Case study 1 — synchronize non-coprime schedules. Merge $x\equiv2\pmod6$ and $x\equiv5\pmod9$. Compute $g=3$, verify compatibility, solve the reduced congruence, and obtain $x\equiv14\pmod{18}$. Replace the second residue with $4$ and explain the contradiction. Success means every accepted result satisfies both inputs and every rejected pair disagrees modulo the gcd.

Case study 2 — reconstruct a large convolution coefficient. Suppose an NTT pipeline returns one coefficient modulo three pairwise coprime transform primes. Compute its Garner digits, evaluate the exact representative when a coefficient bound guarantees uniqueness, and separately evaluate it modulo an application modulus. Verify every source residue and record the source-modulus product.

Hands-on comparison. Generate one thousand seeded systems with two to six small moduli. Compare generalized CRT with brute force through the lcm. For pairwise coprime systems, compare generalized CRT, exact Garner, and modular Garner. Include negative residues, redundant constraints, modulus $1$ in generalized CRT, and deliberate contradictions. Success means all valid methods agree and invalid Garner domains are rejected.

Tiered exercises. Recall: state the gcd compatibility condition. Derive: prove the merged modulus is the lcm. Implement: return the first solution inside a closed interval. Debug: expose overflow from computing $mn/g$ instead of $(m/g)n$. Extend: precompute Garner inverses for repeated reconstructions with a fixed modulus set.

Use incremental generalized CRT when moduli may share factors or contradictions require diagnosis; use Garner when source moduli are pairwise coprime and mixed-radix or target-modular reconstruction avoids unwieldy products. Always distinguish a canonical residue class, an exact representative justified by an external size bound, and a value reconstructed only modulo another modulus.
