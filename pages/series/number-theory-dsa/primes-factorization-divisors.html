Intuition, Vocabulary and Foundations

A prime is an integer greater than $1$ with exactly two positive divisors: $1$ and itself. Composite integers have additional divisors, while $1$ is neither prime nor composite. The Fundamental Theorem of Arithmetic says every $n>1$ has a unique representation

$$ n=p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k} $$

apart from factor order. For example, $360=2^3\cdot3^2\cdot5$.

Every divisor of $360$ is $2^{f_1}3^{f_2}5^{f_3}$ with $0\le f_1\le3$, $0\le f_2\le2$, and $0\le f_3\le1$. Independent exponent choices give

$$ \tau(n)=\prod_{i=1}^{k}(e_i+1), $$

so $\tau(360)=24$. Summing each allowed prime power gives

$$ \sigma(n)=\prod_{i=1}^{k}\left(1+p_i+\cdots+p_i^{e_i}\right) =\prod_{i=1}^{k}\frac{p_i^{e_i+1}-1}{p_i-1}. $$

Thus $\sigma(360)=15\cdot13\cdot6=1170$. The proper-divisor sum is $\sigma(n)-n$ and classifies an integer as deficient, perfect, or abundant.

Prime factorization turns multiplicative questions into independent exponent choices. Once $n=\prod p_i^{e_i}$ is known, divisibility becomes exponent comparison, divisor enumeration becomes a Cartesian product, and $\tau$ and $\sigma$ become products of local contributions.

Step-by-Step Derivations and Algorithms

Trial division tests candidates in increasing order. When $p$ divides the current residual, divide repeatedly and record the exponent. The extracted prime powers times the residual always equal the original input.

If composite $m=ab$, at least one factor is no greater than $\sqrt m$; otherwise $ab>m$. To avoid overflow from $p^2$, use the equivalent condition

$$ p\le\frac{m}{p}. $$

Use the shrinking residual $m$, not only the original input. When the loop stops, any residual greater than $1$ is prime; otherwise it would possess a factor in the tested range.

After extracting $2$ and $3$, every larger prime is congruent to $1$ or $-1$ modulo $6$. Testing $6k\pm1$ candidates skips multiples of $2$ and $3$ but still requires divisibility checks.

Generate divisors incrementally. Begin with $[1]$; for each $p^e$, multiply existing partial divisors by $1,p,\ldots,p^e$. After each stage, the list contains exactly the divisors formed from processed primes.

Trial division preserves that extracted prime powers times the residual equal the original input and that the residual has no prime factor below the next candidate. It takes $O(\sqrt n)$ divisibility tests in the worst case, while listing divisors requires $\Theta(\tau(n))$ output work.

Implementation, Complexity and Engineering

This API accepts positive integers, returns the empty factorization for $1$, and rejects zero and negatives. Signed applications should store the sign separately rather than treating $-1$ as a positive prime.

It extracts $2$ and $3$, then alternates steps of $2$ and $4$ through $6k\pm1$. The overflow-safe condition compares the candidate with the residual divided by the candidate. Divisor statistics use exponents directly; generation occurs only when the divisor values are required.

from __future__ import annotations

from math import prod

Factorization = dict[int, int]


def factorize(n: int) -> Factorization:
    if n < 1:
        raise ValueError("factorization requires n >= 1")
    factors: Factorization = {}

    def extract(prime: int) -> None:
        nonlocal n
        exponent = 0
        while n % prime == 0:
            n //= prime
            exponent += 1
        if exponent:
            factors[prime] = exponent

    extract(2)
    extract(3)
    candidate, step = 5, 2
    while candidate <= n // candidate:
        extract(candidate)
        candidate += step
        step = 6 - step
    if n > 1:
        factors[n] = factors.get(n, 0) + 1
    return factors


def reconstruct(factors: Factorization) -> int:
    return prod(p**e for p, e in factors.items())


def divisor_count(factors: Factorization) -> int:
    return prod(e + 1 for e in factors.values())


def divisor_sum(factors: Factorization) -> int:
    return prod((p ** (e + 1) - 1) // (p - 1) for p, e in factors.items())


def generate_divisors(factors: Factorization) -> list[int]:
    divisors = [1]
    for prime, exponent in sorted(factors.items()):
        previous = divisors[:]
        power = 1
        for _ in range(exponent):
            power *= prime
            divisors.extend(value * power for value in previous)
    return sorted(divisors)


def is_square_free(factors: Factorization) -> bool:
    return all(exponent == 1 for exponent in factors.values())


def run_tests() -> None:
    cases = {
        1: {},
        2: {2: 1},
        29: {29: 1},
        360: {2: 3, 3: 2, 5: 1},
        7560: {2: 3, 3: 3, 5: 1, 7: 1},
        10403: {101: 1, 103: 1},
    }
    for number, expected in cases.items():
        factors = factorize(number)
        assert factors == expected
        assert reconstruct(factors) == number
        divisors = generate_divisors(factors)
        assert len(divisors) == divisor_count(factors)
        assert sum(divisors) == divisor_sum(factors)
        assert all(number % divisor == 0 for divisor in divisors)

    factors = factorize(360)
    assert divisor_count(factors) == 24
    assert divisor_sum(factors) == 1170
    assert is_square_free(factorize(30))
    assert not is_square_free(factorize(12))

    for invalid in (0, -1, -84):
        try:
            factorize(invalid)
        except ValueError:
            pass
        else:
            raise AssertionError("nonpositive input was not rejected")


if __name__ == "__main__":
    run_tests()
    print("all factorization and divisor tests passed")

Applications, Case Studies and Exercises

Prime exponents turn structural questions into small combinatorial calculations. They reveal grid dimensions, sharding factors, scheduling periods, and multiplicative statistics without scanning every integer up to the input.

Practice

Apply Primes, Factorization & Divisor Structure

Case study 1 — Arrange 360 participants

  1. Factor $360=2^3\cdot3^2\cdot5$.
  2. Compute $\tau(360)=24$ possible row lengths.
  3. Pair each divisor $d$ with $360/d$.
  4. Conclude that there are $12$ unordered rectangles because $360$ is not a square.
  5. Generate the divisors and verify the result.

Success criterion: derive the count from exponents and confirm it by generation.

Case study 2 — Choose a production shard count

A system distributes $45{,}360$ records evenly across between $32$ and $256$ shards.

  1. Factor $45{,}360=2^4\cdot3^4\cdot5\cdot7$.
  2. Compute $\tau(45{,}360)=100$.
  3. Generate divisors and filter them to the permitted interval.
  4. For each candidate $d$, calculate the exact load $45{,}360/d$.
  5. Select using operational constraints such as worker count and memory.

Success criterion: produce every feasible shard count and verify exact divisibility.

Tiered exercises

  1. Recall: Classify $1,2,49,97$, and $221$.
  2. Factorization: Factor $7560$ and reconstruct it.
  3. Divisor count: Compute $\tau(7560)$ without listing divisors.
  4. Divisor sum: Derive $\sigma(72)$ from $72=2^3\cdot3^2$.
  5. Proof: Show that a number is a square exactly when every prime exponent is even.
  6. Debugging: Explain why a fixed original square-root bound may do excess work.
  7. Overflow: Replace $p^2\le n$ with an overflow-safe test.
  8. Implementation: Yield divisors lazily without sorting.
  9. Extension: Derive the number of square-free divisors.
  10. Benchmark: Compare odd-only trial division with the $6k\pm1$ wheel.

Use trial division for moderate individual inputs, exponent formulas when only statistics are needed, and output-sensitive generation when divisors themselves are required.
